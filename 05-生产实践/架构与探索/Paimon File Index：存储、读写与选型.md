# Paimon File Index：存储、读写与选型

## 核心结论

File Index 是与数据文件关联的索引数据，用于在查询时进一步缩小需要处理的文件或行的范围。它补充了文件的 min/max 等统计信息：索引能排除某个文件时，就可以避免读取该数据文件；位图索引还可以提供匹配行的位置。索引的收益取决于查询谓词、列的数据分布和索引覆盖情况，同时要付出写入、存储和维护成本。

## 三类索引怎么选

| 索引 | 适合的查询 | 判断方式与代价 |
|---|---|---|
| Bloom Filter | 高基数列的等值查询，如按 `user_id` 查找 | 判断“不存在”可用于排除文件；判断“可能存在”仍需读取，存在误判 |
| Bitmap | 低基数列的等值、集合过滤，如 `status` | 记录值对应的行位置，结果更精确，但可能占用更多空间 |
| BSI／范围位图 | 数值等字段的范围过滤 | 用位图支持范围判断；具体名称、类型与配置项须按所用 Paimon 版本核对 |

**版本提醒：**原文使用 `file-index.bsi.columns`，Apache Paimon 1.1 文档也记录了 BSI；较新的 1.4 和 master 文档使用 `file-index.range-bitmap.columns`。不要直接把原文配置复制到未确认版本的集群。

## 索引存在哪里

一份数据文件可以关联多个列、多个类型的索引。索引内容较小时可嵌入 Manifest 中的数据文件元信息；较大时存成数据文件旁的独立索引文件。索引文件将列名、索引类型和偏移等信息放在头部，具体索引字节放在主体中。

这个区别影响读取时机：扫描 Manifest 时可以利用已嵌入的索引；外部索引文件需要在后续读取阶段额外访问。原文提到的具体大小阈值属于版本相关配置，使用前应查当前版本。

## 写入与读取过程

**写入：**数据写入器按配置把每行的列值交给相应索引写入器；数据文件完成时生成索引，并决定嵌入元信息还是写为独立文件。因此，建立索引会增加写入及后续维护工作。

**读取：**

1. 扫描 Manifest，先利用文件统计信息和可用的嵌入索引排除文件。这里仍要读取 Manifest；节省的是被排除文件的数据读取。
2. 对保留的文件，在读取阶段评估嵌入或外部索引。索引可能进一步排除整个文件，或通过位图提供候选行位置。
3. 最终效果还取决于读取器、谓词和数据布局。获得候选行位图不等于只产生对应行的物理 I/O。

## 给已有数据补建索引

修改表的索引配置只影响之后写入的数据文件。要为已有文件建索引，可使用 `rewrite_file_index`。该过程需要读取构建索引所需的数据，但不必重写原数据文件。Flink 和 Spark 的调用语法、分区参数不同，应按实际引擎与版本使用。

## 实际使用时如何验证

1. 确认 Paimon 版本、表类型，以及目标列的谓词形式和基数。
2. 只给常用于过滤、且有望明显减少读取量的列配置索引。
3. 检查索引覆盖了哪些数据文件；有索引不代表查询一定用了索引。
4. 对比建索引前后的查询计划、扫描文件数、读取量和耗时，同时观察写入开销与索引空间。
