# 数据生命周期与分区清理

返回：[[00-首页/导航-按数仓开发流程|按数仓开发流程导航]]

## 核心原则

保留策略可以同时考虑“保留多久”和“保留多密”：年龄小于 A 的分区完整保留；A 到 B 之间只保留周末或月末快照；超过 B 才删除。这比统一保留期更适合既要近期排障细节、又要长期趋势分析的数仓。

配置至少明确表名、A/B 阈值、周末/月末规则、单日删除上限和 dry-run 模式。执行前应同时核对 Metastore 分区与底层路径的时间，输出待执行 SQL 并限制批量。例如分区名错误地写成未来日期时，仅按目录名批量删除会误删真实数据；dry-run 和删除上限能让错误先暴露。

还应先确认下游没有依赖待删分区，再执行并记录审计结果。删除完成后需要验证 Metastore、底层文件和查询结果三者一致，不能只把 `DROP PARTITION` 执行成功当作清理完成。

## 执行检查清单

- 明确保留周期和保留密度，区分近期明细、中期快照与长期删除。
- 同时核对分区值、Metastore 元数据和底层文件路径。
- 默认先执行 dry-run，输出拟删除分区、路径和预计数据量。
- 设置单批、单日删除上限，避免配置错误扩大影响面。
- 删除前检查下游任务、补数流程、审计与合规保留要求。
- 保留操作日志和可回滚窗口；对象存储需结合版本控制或回收站能力。
- 删除后复核元数据、文件和查询结果，确认没有孤儿路径或悬空分区。
