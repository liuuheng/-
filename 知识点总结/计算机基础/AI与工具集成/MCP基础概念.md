# MCP基础概念

> **内容摘要：** MCP是一套让AI统一发现和调用外部工具的通信协议，而不是某个具体脚本。MCP Server可以使用Python、Java或Node.js实现，负责接收AI生成的结构化参数，调用第三方API、数据库或本地程序，再把结果返回给AI分析。它可以理解为面向AI的“统一工具接口标准”。

## 一、基本定义

MCP全称为`Model Context Protocol`，中文可译为“模型上下文协议”。

它定义了AI应用如何：

- 发现外部工具提供的能力；
- 理解工具的用途和参数；
- 向工具传递结构化参数；
- 接收工具返回的数据；
- 根据返回结果继续分析和回答。

## 二、基本调用流程

```text
用户提出问题
→ AI判断需要使用外部工具
→ AI选择合适的MCP工具
→ AI从自然语言中提取参数
→ MCP Server调用第三方API、数据库或本地程序
→ MCP Server返回结构化数据
→ AI分析数据并组织答案
```

例如用户询问“今天杭州天气怎么样”：

```text
AI选择天气查询工具
→ 传入城市“杭州”和当天日期
→ 天气服务返回晴天、温度、湿度等数据
→ AI将数据整理成自然语言答案
```

## 三、MCP与脚本的关系

MCP不是Python脚本，而是一套通信规范。

MCP Server可以使用以下方式实现：

- Python脚本；
- Java或Node.js服务；
- 对第三方HTTP API的封装；
- 数据库客户端；
- 本地命令行程序。

更准确地说：**Python脚本可以实现MCP Server，而MCP规定这个程序如何向AI描述工具、接收参数和返回结果。**

## 四、MCP与普通API的区别

- 普通API主要规定“系统如何被开发人员调用”。
- MCP进一步规定“如何向AI描述工具、参数、返回结果和操作权限”。

API通常是具体服务自身的接口；MCP则在AI与各种API之间提供统一的调用规范。

## 五、MCP与Postman的区别

两者都可以传递参数、调用接口并接收JSON等结构化结果，但使用方式不同：

| 对比项 | Postman | MCP |
|---|---|---|
| 主要使用者 | 开发人员 | AI模型或Agent |
| 接口选择 | 人工选择 | AI根据问题自动选择 |
| 参数填写 | 人工填写 | AI从自然语言中提取 |
| 返回结果 | 人工查看和判断 | AI继续分析并回答 |
| 主要用途 | API开发与调试 | 让AI使用外部工具和数据 |

可以简单理解为：**Postman是人类手动调用接口的工具，MCP是让AI自动发现和调用工具的统一协议。**

## 六、一句话总结

> MCP负责连接，MCP Server负责执行，外部系统负责提供真实数据，AI负责理解需求并分析结果。
