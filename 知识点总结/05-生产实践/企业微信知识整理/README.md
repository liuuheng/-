## 贯穿所有主题的判断框架

面对一个数据问题，建议依次回答以下问题，而不是先写 SQL：

1. **业务目标是什么？** 是审计业务真实发生、支撑指标统计，还是服务某个报表或接口？
2. **统计对象是谁？** 是用户、企业、订单、方案、素材，还是一次行为？对象不同会直接改变粒度和指标含义。
3. **一行代表什么？** 如果无法用一句完整的话描述粒度，模型通常还没有设计完成。
4. **时间锚点是什么？** 按注册时间、行为发生时间、支付时间还是数据入仓时间统计？是否允许跨周期？
5. **数据会不会更新、迟到或重复？** 这决定使用覆盖、拉链、去重、Watermark、版本号还是幂等写入。
6. **正确性如何验证？** 至少要有行数、主键、空值、枚举、金额守恒和新旧表对账。
7. **性能瓶颈在哪里？** 先看执行计划、扫描量、Shuffle、状态和数据分布，再调参数。
