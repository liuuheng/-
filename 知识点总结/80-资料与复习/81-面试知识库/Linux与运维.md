##### Linux 与运维

##### Linux 日常排障命令

Q：大数据开发常用哪些 Linux 命令？线上任务变慢时如何组合使用，而不是只背命令？
A：我按 CPU、内存、磁盘、网络和进程逐层看。先用 `top/ps -ef` 找异常进程和线程，`free -h`、`vmstat 1` 判断内存与上下文切换，`iostat -xz 1` 看磁盘 await/util，`df -h/du -sh` 查空间，`ss -lntp` 和 `sar -n DEV 1` 看端口与网络。日志用 `tail -F`、`grep -n`、`awk`、`sed`，大文件先按时间或关键字过滤，避免直接打开。Java 进程再结合 `jstack`、GC 日志和 heap dump；Flink/Spark 还要回到 Web UI 对照 subtask/task 指标。每条命令都保留时间、主机和输出证据，修改配置前先复现并确定瓶颈。

##### 知识点补充

`load average` 高不一定是 CPU 高，也可能是不可中断 IO；内存 used 高也可能只是 page cache。诊断要结合多项指标和时间线。

##### 文件去重的 Shell 实现

Q：文件每行一个单词，如何用 Linux 命令去重？如果文件很大怎么办？
A：不要求保序时用 `LC_ALL=C sort input.txt | uniq > output.txt`，其实 `sort -u input.txt -o output.txt` 更直接；需要统计频次则 `sort input.txt | uniq -c | sort -nr`。要求保持首次出现顺序，可用 `awk '!seen[$0]++' input.txt > output.txt`，但 awk 的哈希表会随唯一值增长，超大文件可能内存不足。大文件优先使用 `sort -u`，通过 `-T` 指定临时盘、`-S` 控制内存，并确认临时空间足够。完成后比较输入输出行数、抽样内容和校验和；不能用 `uniq` 直接处理未排序文件，因为它只去相邻重复。

##### 知识点补充

`sort` 受 locale 影响，固定 `LC_ALL=C` 可提高速度并使排序稳定可解释。覆盖原文件时先写临时文件并原子替换，避免命令失败损坏源数据。

##### 终止父进程及所有子进程

Q：Shell 中如何安全停止一个父进程及其所有子进程？
A：先确认 PID 和进程树，用 `ps -o pid,ppid,pgid,cmd -p PID`、`pgrep -P PID` 或 `pstree -p PID`，避免误杀。若进程由同一 process group 启动，优先向整个进程组发送 `TERM`：`kill -TERM -- -PGID`，等待超时后再 `KILL`；否则递归收集最深层子进程，先停子再停父，防止父进程继续派生。生产服务更应该通过 systemd、YARN 或 Kubernetes 控制器停止，让它执行 checkpoint、关闭连接和清理临时文件。脚本要校验 PID 非空、不是 1/当前 shell，记录命令行并二次确认，绝不能 `pkill -f` 模糊匹配后直接强杀。

##### 知识点补充

SIGTERM 可被进程捕获以优雅退出，SIGKILL 不能捕获。父进程退出后子进程可能被 reparent，因此仅 kill 父 PID 不保证子进程结束。

##### 运维与故障定位能力

Q：你做过哪些组件运维工作？遇到线上问题如何定位并形成闭环？
A：我会用一个真实闭环回答，例如 Flink 延迟升高：告警显示 Kafka lag 增长，先确认 Source 输入正常，再从拓扑下游向上找第一个 busy 100% 的 Sink；线程栈显示 JDBC 阻塞，数据库连接池等待高。临时限流并扩 Sink 并行度止血，随后改成批量异步写、设置超时和熔断，压测验证 P99 与数据库 QPS，灰度后监控 24 小时。最后补充连接池等待、批次失败和 lag 组合告警，更新 runbook 与容量模型。运维不只是执行重启，还包括变更审批、备份恢复、升级演练、SLA、故障复盘和自动化，回答必须说明证据、风险控制和验证结果。

##### 知识点补充

有效排障遵循“先止血、再定位、后根治”，同时保留日志、指标、发布版本和时间线。重启能恢复不代表根因解决。

##### Shell 单中括号与双中括号

Q：Shell 中 `[ ]` 和 `[[ ]]` 有什么区别，写脚本时怎么避免条件判断错误？
A：`[ ]` 本质上是 test 命令，兼容 POSIX shell，变量展开后容易受空值和单词分割影响，因此字符串变量通常要加双引号；数值比较使用 `-eq/-lt`，字符串比较用 `=`。`[[ ]]` 是 Bash/Ksh 条件语法，不做普通的单词分割和路径名展开，支持 `&&`、`||`、正则 `=~` 和模式匹配，复杂判断更安全，但不保证 `/bin/sh` 可用。实际脚本开头明确解释器并启用严格模式，参数先校验；文件判断用 `-f/-d/-r`。上线前用 shellcheck，测试空字符串、空格、通配符和命令失败路径。

##### 知识点补充

算术判断可用 `(( ))`，避免把字符串比较和数值比较混淆。严格模式需要配合有意允许失败的命令处理，不能机械添加后不测试。

##### vi/vim 常用模式与批量编辑

Q：vi 有哪些模式，如何跳转行和批量注释？
A：常用是普通模式、插入模式和命令行模式；打开后默认普通模式，`i/a/o` 进入插入，Esc 返回，`:` 进入命令行。跳到第 N 行用 `Ngg` 或 `:N`，`gg/G` 到首尾，`:set number` 显示行号。批量注释可用可视块：Ctrl+V 选择多行行首，按 `I` 输入注释符后 Esc；批量取消可选中注释列后 `d`，也可用范围替换如 `:10,20s/^/#/`。修改配置前先复制文件或用版本控制，保存 `:w`、退出 `:q`，强制操作前确认目标，避免误改生产文件。

##### 知识点补充

vi 的术语在不同资料中会把可视模式单列。面试回答应能给出实际按键，并说明批量操作的范围和回退方式。

##### Shell 按末列去重与求和

Q：制表符文件怎样按最后一列去重，或对某列求和？
A：数据不大且只保留任意一条时，可用 awk，以 `$NF` 作为最后一列：`!seen[$NF]++` 时输出整行；求和则在主体中 `sum += $N`，END 打印 sum。若要保留最后一条，awk 扫描时按 key 覆盖整行，END 再输出，但关联数组顺序不稳定；要保持原顺序或选最新时间，我会先明确规则，再用 sort 的稳定键配合 awk。处理 TSV 时显式设置 `-F '\t'` 和输出分隔符，先检查空列、表头及末列是否含空白。

##### 知识点补充

超大文件的 awk 去重会让 key 集合占满内存，可先外部 sort 再线性 unique。金额应确认小数精度，awk 浮点不适合严格财务对账。

##### 依赖漏洞与框架缺陷处置

Q：生产框架发现安全漏洞或严重 Bug，你如何升级并控制风险？
A：我先确认受影响版本、可利用条件、暴露面和数据权限，临时通过网络隔离、关闭危险接口或限权降低风险；随后在分支中升级到官方修复版本，核对依赖冲突、配置变化、状态/协议兼容和回滚限制。测试包括单元、集成、历史作业回放、性能及故障恢复，先灰度非核心任务，再分批升级核心集群，期间监控错误率、延迟、资源和数据对账。若暂时不能升级，必须记录风险接受人、补偿措施和截止时间，不能无限期忽略。

##### 知识点补充

安全漏洞与功能 Bug 都要保留版本清单、变更记录和回滚包。只升级客户端或只升级服务端是否有效，要以官方兼容矩阵和复现结果判断。

##### Linux 磁盘挂载

Q：Linux 新增磁盘后怎样挂载，并保证重启后有效？
A：先用 `lsblk`、`blkid` 确认设备和现有文件系统，避免选错盘；新盘按方案分区或建 LVM，再用 ext4/xfs 格式化。创建挂载点后先手工 mount，检查容量、权限和读写；最后把 UUID 而不是易变化的 `/dev/sdX` 写入 `/etc/fstab`，用 `mount -a` 验证语法再重启。生产操作前核对是否已有签名和数据，扩容文件系统也要区分 xfs/ext4 命令，不能直接 mkfs 覆盖。

##### 知识点补充

挂载目录原有文件会被遮住而非删除。集群还要设置 owner、权限、容量告警和坏盘替换流程。

##### Linux 网络配置与网卡定位

Q：Linux 网卡配置文件在哪里，网络异常时怎么排查？
A：路径取决于发行版：传统 CentOS 常见 `/etc/sysconfig/network-scripts/ifcfg-*`，Ubuntu 可能用 netplan，现代系统也常由 NetworkManager 管理，不能背一个固定路径。排障先用 `ip addr/link/route` 看地址、状态和路由，用 `ss` 看监听，ping 网关、dig 查 DNS，必要时 tcpdump 抓包；同时检查防火墙、网卡错误计数和云安全组。修改前备份配置，通过受控方式 reload，并保留远程会话，避免改错后失联。

##### 知识点补充

`ip` 是现代首选命令。配置路径、服务名和重载方式必须以系统版本为准。

##### Shell 引号、参数与批量替换

Q：Shell 的单引号、双引号和 `$1` 有什么含义？怎样批量替换目录中的文本？
A：单引号内变量和命令替换都不展开，双引号会展开 `$var`、`$(cmd)`，但保留空格为一个参数；无引号容易发生分词和通配符扩展，所以路径变量通常写 `"$file"`。`$1` 是脚本第一个位置参数，`${10}` 才是第十个，脚本先检查参数数量和路径。批量替换我先用 `rg -l 'text' target` 列出并抽样，再对明确文件调用 `sed` 生成备份或在版本控制中修改，最后再次搜索和 diff；不对未知二进制文件或根目录执行递归替换。

##### 知识点补充

macOS/BSD 与 GNU sed 的原地编辑参数不同，生产脚本应验证环境。涉及特殊字符时优先选安全分隔符并正确转义。

##### Shell 定时与循环脚本

Q：如何写 1 到 100 的输出，并把脚本设置为定时执行？
A：Bash 可用 `for i in {1..100}; do echo "$i"; done`，需要变量边界时用 `for ((i=1;i<=n;i++))`。定时执行可用 cron：写绝对脚本路径、解释器和日志路径，显式设置 PATH、时区和业务日期；脚本内部用锁文件或 `flock` 防止上次未完成又启动，处理退出码并让失败触发告警。上线前先在同一运行用户下手工执行，cron 环境比交互 shell 精简，不能依赖当前目录和个人环境变量。

##### 知识点补充

分布式数据任务更适合调度平台，能提供依赖、补跑和审计。cron 只适合简单单机任务。
