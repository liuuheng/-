## 深入理解（新增）

生成较长的中间步骤可以给模型更多计算路径，却不保证步骤正确，也不保证文本忠实描述内部因果过程。验证应落在答案、约束满足、可执行计算或可核查证据上，而不是“看起来思考充分”。

训练推理模型时，奖励可来自规则验证、单元测试或人工偏好。格式奖励容易被模型钻空子，若答案错误但格式完整仍能获得高分，就会把预算花在包装而非解题。

比较方法时应固定问题集、最大生成 token、采样次数与验证器。多次采样再筛选的准确率不能和单次生成直接比较；同时报告 pass@1、候选预算与验证器错误，才能判断收益来自模型还是搜索。



## 核心代码（新增）

以下是可在 CPU 运行的机制或业务契约示例，完整源码与测试见 [[知识点总结/80-资料与复习/81-面试知识库/08-大模型高频面试题/06-代码实验/01-核心代码实验与验证范围|核心代码实验与验证范围]]。示例不包含完整模型训练或外部平台部署。

```python
import numpy as np

def grpo_advantages(rewards, eps=1e-8):
    rewards = np.asarray(rewards, dtype=float)
    if rewards.ndim != 2:
        raise ValueError("shape must be [prompts, completions_per_prompt]")
    return (rewards - rewards.mean(axis=1, keepdims=True)) / (rewards.std(axis=1, keepdims=True) + eps)

a = grpo_advantages([[0, 1, 2], [1, 1, 1]])
assert np.allclose(a[1], 0)  # 全组奖励相同，没有相对区分信号。
```

### 思维链

<!-- source-block:1376 -->
#### 什么是思维链？思维链有什么作用？

<!-- source-block:1377 -->
思维链（Chain of Thought，CoT） 是让AI模仿人类分步推理的技术，核心是将复杂问题拆解为多个中间步骤展示出来。本质是一种提升AI推理可靠性与透明度的实用技术，推动输出从“答案”转向“过程”。

<!-- source-block:1378 -->
作用：

<!-- source-block:1379 -->
**提高复杂任务准确率（尤其数学、逻辑推理等）。**

<!-- source-block:1380 -->
**增强可解释性（暴露推理过程，便于理解与纠错）。**

<!-- source-block:1381 -->
**拓展能力边界（支持多步骤规划、代码生成等深层任务）。**

<!-- source-block:1382 -->
#### 如何微调出带有思维链的LLM推理模型？

<!-- source-block:1383 -->
**PPO：奖励模型奖励那些带思维链的输出。**

<!-- source-block:1384 -->
**DPO：正例数据带有思维链，负例数据不带思维链。**

<!-- source-block:1385 -->
**GRPO：使用基于规则的奖励函数微调LLM。**

<!-- source-block:1386 -->
在不微调的情况下，使用推理时间扩展，来让LLM产生带有思维链的输出。本质上是PromptEngineering。

<!-- source-block:1387 -->
#### 带有思维链的推理模型优缺点？

<!-- source-block:1388 -->
| 擅长 | 不擅长 |
| --- | --- |
| 演绎或者归纳推理（如解谜题、数学证明） | 快速且粗略的回答（更多的推理时间） |
| 思维链式推理（分解多步骤问题） | 基于知识的任务（容易产生幻觉） |
| 复杂决策任务 | 简单任务（过度思考） |
| 对新问题有更好的泛化能力 | <br> |

#### 现阶段LLM的对齐阶段分为sft和rlhf阶段，我们可以跳过sft阶段直接进行rlhf么？

<!-- source-block:1390 -->
当然可以。GRPO就可以做到这一点。让模型自动产生思维链。然后训练出了DeepSeek-R1-Zero。但有SFT数据集不用也太浪费了，所以一般都是在sft微调后的模型上做rlhf。
