## 深入理解（新增）

哈希表两数之和的关键不变量是：处理位置 i 之前，seen 只包含更早元素。因此先查补数再写入当前元素，可以防止同一元素被使用两次。重复值不是特殊补丁，而是由这个顺序自然处理。

平均 O(1) 的哈希访问依赖哈希分布；整个算法的空间代价是 O(n)。如果输入已排序且只需判断是否存在，双指针可以减少额外空间，但排序本身有成本，返回原下标时还需保留映射。

复杂度之外要说明失败契约：无解时返回 None 还是抛异常，多组答案时返回哪一组，空输入如何处理。大模型生成代码后，应测试这些边界和不变量，不能只用一个正常样例证明正确。



## 核心代码（新增）

以下是可在 CPU 运行的机制或业务契约示例，完整源码与测试见 [[知识点总结/80-资料与复习/81-面试知识库/08-大模型高频面试题/06-代码实验/01-核心代码实验与验证范围|核心代码实验与验证范围]]。示例不包含完整模型训练或外部平台部署。

```python
def two_sum(values, target):
    seen = {}
    for index, value in enumerate(values):
        if target - value in seen:
            return seen[target - value], index
        seen[value] = index
    return None

assert two_sum([3, 3], 6) == (0, 1)
assert two_sum([3], 6) is None
```

### 数据结构与算法

<!-- source-block:102 -->
#### 常用数据结构

<!-- source-block:103 -->
##### 线性数据结构（元素之间一对一线性关系）

<!-- source-block:104 -->
**栈（Stack）**

<!-- source-block:105 -->
核心规则：先进后出（LIFO），只有一端（栈顶）能进行增删操作，栈底封闭。

<!-- source-block:106 -->
**队列（Queue）**

<!-- source-block:107 -->
核心规则：先进先出（FIFO），一端（队尾）入队，一端（队首）出队）

<!-- source-block:108 -->
**链表（Link List）**

<!-- source-block:109 -->
核心结构：由一个个「节点」组成，每个节点包含「数据」和「下一个节点的引用」（类似链条），分单链表、双链表、循环链表。

<!-- source-block:110 -->
核心特点：

<!-- source-block:111 -->
优点：插入 / 删除中间元素效率高（只需修改节点引用，无需移动其他元素），内存分配灵活（无需连续内存）。

<!-- source-block:112 -->
缺点：随机访问效率低（无索引，需从头节点遍历到目标节点），占用额外内存存储节点引用。

<!-- source-block:113 -->
##### 非线性数据结构（元素之间一对多/多对多关系）

<!-- source-block:114 -->
**树（Tree）**

<!-- source-block:115 -->
核心结构：分层树形结构，有且只有一个「根节点」，每个节点可以有多个子节点，无环（节点之间不会形成闭环）。

<!-- source-block:116 -->
高频之类及其特点：

<!-- source-block:117 -->
**二叉树：每个节点最多有 2 个子节点（左、右子节点），是最基础的树结构，支持前 / 中 / 后 / 层序四种遍历。**

<!-- source-block:118 -->
**二叉搜索树（BST）：二叉树的升级版，左子树所有节点值 &lt;根节点值，右子树所有节点值&gt; 根节点值，支持高效查找 / 插入 / 删除（平均 O (logn)）。**

<!-- source-block:119 -->
**红黑树/AVL树：平衡二叉搜索树，避免二叉搜索树退化为链表，保证查找 / 插入 / 删除的高效性（底层用于字典、集合等）。**

<!-- source-block:120 -->
**图（Graph）**

<!-- source-block:121 -->
核心结构： 由节点和边组成，允许有环，是最通用的复杂数据结构。

<!-- source-block:122 -->
- 分类：按照边的方向可以划分为有向图和无向图，按照边的权重可以分为带权图和无权图。

<!-- source-block:123 -->
- 存储方式：邻接表（节省内存适合稀疏图），邻接矩阵（查找高效，适合稠密图）

<!-- source-block:124 -->
#### 算法

<!-- source-block:125 -->
##### \*\*时间复杂度和空间复杂度的定义是什么？

<!-- source-block:126 -->
时间复杂度：描述算法执行的基本指令数随输入规模 n 的增长趋势，用大 O 表示（如 O (n)、O (logn)），通常关注最坏情况。

<!-- source-block:127 -->
空间复杂度：描述算法内存空间随输入规模 n 的增长趋势，同样用大 O 表示，关注数据占用的空间。

<!-- source-block:128 -->
##### 常见时间复杂度的排序是什么？

<!-- source-block:129 -->
O(1) &lt; O(logn) &lt; O(n) &lt; O(nlogn) &lt; O(n²) &lt; O(n·2ⁿ) &lt; O(n·n!) &lt; O(nⁿ)。

<!-- source-block:130 -->
##### 二分查找的适用条件及时间复杂度？

<!-- source-block:131 -->
- 适用条件：有序数组（升序或降序）。

<!-- source-block:132 -->
- 原理：每轮将搜索范围缩小一半，直至找到目标或范围为空。

<!-- source-block:133 -->
- 时间复杂度：O (logn)，空间复杂度 O (1)。

<!-- source-block:134 -->
##### 快速排序和归并排序的核心思想及复杂度对比？

<!-- source-block:135 -->
| 算法 | 核心思想 | 时间复杂度（平均） | 空间复杂度 |
| --- | --- | --- | --- |
| 快速排序 | 选择基准值，将数组分为小于和大于基准的两部分，递归排序子数组 | O(nlogn) | O(logn) |
| 归并排序 | 分治思想，将数组拆分至单个元素，再合并两个有序子数组 | O(nlogn) | O(n) |

<!-- source-block:136 -->
##### 动态规划和分治算法的区别？

<!-- source-block:137 -->
分治算法：将问题拆分为独立子问题，递归求解后合并结果（如归并排序）。

<!-- source-block:138 -->
动态规划：处理子问题重叠的场景，通过存储子问题结果避免重复计算（如爬楼梯、0-1 背包）。

<!-- source-block:139 -->
##### 贪心算法的适用条件及案例？

<!-- source-block:140 -->
适用条件：问题需满足贪心选择性质（局部最优可导出全局最优）和最优子结构。

<!-- source-block:141 -->
案例：分发糖果（每个孩子至少 1 颗，评分高的孩子需比相邻孩子多），通过左右两次遍历确保局部最优。

<!-- source-block:142 -->
##### 回溯算法的基本步骤及案例？

<!-- source-block:143 -->
步骤：选择候选解→递归探索→验证条件→回溯（撤销选择）。

<!-- source-block:144 -->
案例：N 皇后问题，通过递归尝试放置皇后，验证列和对角线无冲突，冲突则回溯。
