##### 二分查找峰值

Q：LeetCode 162，如何用二分法找到峰值元素？
A：我用闭区间 `[left,right]` 二分，并比较 `nums[mid]` 与 `nums[mid+1]`。若前者更大，当前位置处在下降坡，`[left,mid]` 中一定存在峰值，所以 `right=mid`；否则峰值在 `[mid+1,right]`，令 `left=mid+1`。循环条件是 `left<right`，这样 `mid` 一定小于 right，访问 `mid+1` 不越界；收敛后返回 left。比如 `[1,2,3,1]`，第一次比较 2 和 3 向右，第二次比较 3 和 1 向左，最终定位下标 2。复杂度 `O(log n)`、空间 `O(1)`。我还会说明题目两端视为负无穷，因此沿上坡方向一定能遇到某个峰值，不要求找到全局最大值。

```java
int findPeakElement(int[] nums) {
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] > nums[mid + 1]) right = mid;
        else left = mid + 1;
    }
    return left;
}
```

##### 知识点补充

循环条件 `left < right` 保证访问 `mid + 1` 安全。核心依据是沿上坡方向最终一定能遇到峰值，题目通常把数组两侧视为负无穷。

##### Java 内存模型

Q：讲一下 Java Memory Model。
A：JMM 解决共享变量的可见性、有序性和原子性，不是堆、栈、方法区的划分。实际例子是一个线程循环读取 `running`，另一个线程把它改为 false；没有同步时读取线程可能一直使用缓存值。把字段声明为 `volatile` 后，写入 happens-before 后续读取，并禁止相关重排序，适合状态开关和单次发布；但 `count++` 是读、改、写三步，volatile 仍会丢更新，需要 `AtomicInteger` 或锁。实现单例双重检查时实例字段也必须 volatile，防止引用先发布、对象尚未初始化。线上遇到偶发并发错误，我会先画线程间共享数据和 happens-before，再用线程 dump、压测和 jcstress 类测试验证，而不是靠增加 sleep。

##### 知识点补充

关键 happens-before 包括程序次序、监视器解锁先于后续加锁、volatile 写先于后续读、线程 start 和 join 规则。面试时要区分 JMM 与堆、栈、方法区等运行时数据区。

##### Array、ArrayList 与 LinkedList

Q：数组和 List 有什么区别？ArrayList 与 LinkedList 的读写性能怎么比较？
A：数组长度固定、可存基本类型、按下标访问；List 是接口，集合实现通常动态扩容且存对象。ArrayList 底层是连续对象数组，随机访问 `O(1)`，尾部追加摊销 `O(1)`，中间插删要移动元素。LinkedList 是双向链表，已拿到节点时插删是 `O(1)`，但按下标查找是 `O(n)`，而且对象和指针开销大。实际业务我默认 ArrayList，只有明确需要频繁在已定位节点附近插删时才考虑 LinkedList。

##### 知识点补充

不能笼统说 LinkedList 插入一定更快：按索引插入前先遍历定位，整体仍是 `O(n)`。ArrayList 扩容会复制数组，但连续内存访问具有更好的缓存局部性。

##### 三角形数组问题

Q：无序数组中任选三条边，如何求最大三角形周长？如何统计有效三角形数量？
A：最大周长问题先升序排序，然后从最大边开始向前检查连续三个数。若 `a[i-2] + a[i-1] > a[i]`，这三个数就是当前能得到的最大周长；不满足时最大边无法与更小的两边组成三角形，继续左移，复杂度主要是排序的 `O(n log n)`。统计数量时固定最大边 `k`，用左右指针；若 `a[left] + a[right] > a[k]`，则从 `left` 到 `right-1` 与 `right` 都满足，可一次累加 `right-left`，再右指针左移，否则左指针右移。

##### 知识点补充

前提通常是边长为正数；若输入允许非正数要先过滤。最大周长是贪心扫描，数量统计是排序加双指针，两题不能只套同一段代码。

##### 链表插入方式与一次遍历反转

Q：链表头插和尾插有什么区别？如何一次遍历完成单链表反转？
A：头插把新节点的 `next` 指向当前头，再更新头节点，单次是 `O(1)`，但连续头插会把输入顺序反转。尾插若维护 tail 指针也是 `O(1)`，能保持输入顺序；没有 tail 时每次找尾部会退化为 `O(n)`。反转单链表时维护 `prev`、`curr`、`next` 三个引用：先保存 `curr.next`，再让 `curr.next=prev`，然后整体向前推进，遍历结束返回 `prev`，时间 `O(n)`、额外空间 `O(1)`。

##### 知识点补充

必须先保存 next 再改指针，否则后续链会丢失。需要明确处理空链表、单节点和是否有虚拟头节点；双向链表反转还要同时交换 `prev` 与 `next`。

##### JVM 垃圾回收与排障

Q：你对 Java GC 了解多少，线上如何判断是不是 GC 问题？
A：我先从可达性和分代讲：对象不可达后才有机会回收，新对象通常进入年轻代，存活对象晋升；不同收集器用复制、标记清除或标记整理组合控制吞吐和停顿。线上不会只看一次 Full GC，而会结合 GC 日志、暂停时间、频率、分配速率、晋升、老年代占用和应用延迟判断。若堆持续上涨且 Full GC 后不下降，再用 heap dump 和 dominator tree 查泄漏；若只是分配过快，则优化对象生命周期、批次或堆配置。

##### 知识点补充

常见收集器包括 G1、ZGC 等，选型取决于 JDK 版本、堆大小、吞吐和停顿目标。Flink 作业还要区分 JVM heap OOM、direct memory、metaspace、RocksDB native memory 和容器超限。

##### 奇偶字符稳定分组

Q：字符串 `12345` 中奇数放前、偶数放后，并保持各自原顺序，如何实现？
A：这是稳定分区问题，我会先确认输入只含数字字符以及是否允许额外空间。允许空间时遍历一次，先用 `StringBuilder odd` 和 `even` 分别追加，判断方式是 `int value=ch-'0'; (value&1)==1`，最后返回 `odd.append(even)`，`12345` 得到 `13524`；时间 `O(n)`、空间 `O(n)`，各组相对顺序天然不变。若要求原地且稳定，普通首尾双指针会破坏顺序，必须在发现奇数位于偶数后方时做区间右移，最坏 `O(n²)`，或者使用分治稳定划分。编码时会覆盖空串、全奇、全偶、包含非数字字符的策略，并明确不把字符 ASCII 奇偶当成业务数字奇偶。

##### 知识点补充

判断字符数字要先验证 `Character.isDigit` 或明确输入只含数字，再用 `(ch - '0') % 2` 判断。若输入是整数数组，思路相同；若不要求稳定，可用双指针原地交换。

##### 全排列回溯

Q：输入 `[1,2,3]`，如何生成全部排列？
A：我用回溯维护 `path` 和 `used[]`。每层遍历所有下标，若未使用就标记、加入路径、递归，返回后删除最后一个元素并恢复标记；当 `path.size()==nums.length` 时必须 `new ArrayList<>(path)` 复制结果。对 `[1,2,3]`，第一层选 1，第二层分别选 2/3，完成两条路径后回退，再从 2、3 开始，共得到 6 个排列。若数组含重复值，先排序，并用 `i>0 && nums[i]==nums[i-1] && !used[i-1]` 跳过同层重复分支。复杂度约 `O(n×n!)`，这是输出规模决定的；空数组返回包含空排列还是空列表要按接口约定说明。

##### 知识点补充

时间复杂度约为 `O(n × n!)`，因为输出本身就有 `n!` 个、每个复制长度为 n。回溯必须复制路径保存结果，不能直接保存同一个可变 List 引用。

##### 驼峰命名转换

Q：如何在下划线命名和驼峰命名之间转换？
A：我会先确定转换方向和缩写规则。下划线转小驼峰时单次扫描，遇到 `_` 设置 `upperNext=true`，下一个有效字母转大写并清除标记，例如 `user_login_time` 得到 `userLoginTime`；连续或首尾下划线按约定跳过或报错。驼峰转下划线时不能简单遇大写就加下划线，否则 `URLValue` 会变成 `u_r_l_value`。我会把“连续大写结束且后面跟小写”的位置视为单词边界，使其转换为 `url_value`。实现后至少测试空串、单词、数字、连续下划线、首字母大写和连续缩写，时间 `O(n)`，避免用多轮正则造成边界不可控。

##### 知识点补充

正则替换代码短但边界和性能不一定更好，面试手写更适合状态机扫描。若要求 `URLValue` 转换，需要明确期望是 `url_value` 还是 `u_r_l_value`，不同命名规范处理连续大写的规则不同。

##### HashMap 实现原理

Q：讲一下 Java HashMap 的底层实现。
A：JDK 8 的 HashMap 是数组加链表/红黑树。key 的 hash 经扰动后定位桶，冲突时比较 hash 和 `equals`；链表达到树化阈值且数组容量足够时转成红黑树。元素超过 `capacity × loadFactor` 会扩容，容量通常翻倍，并利用高位 bit 把节点留在原索引或移动到“原索引 + 旧容量”。HashMap 不是线程安全的，并发写我会用 ConcurrentHashMap。

##### 知识点补充

默认负载因子 0.75；树化阈值通常为 8，容量小于 64 时优先扩容。正确实现自定义 key 必须同时满足 `equals` 与 `hashCode` 契约，可变字段不应参与已入表 key 的哈希。

##### Java 创建并发任务的方式

Q：Java 创建多线程有哪些方式？生产中如何正确创建线程池？
A：语言层面可以继承 `Thread`、实现 `Runnable`，需要返回值和异常时用 `Callable` 配合 `Future`。生产代码一般把任务提交给 `ExecutorService` 或 `CompletableFuture`，避免每个任务直接 new Thread。真正创建线程池时我会显式使用 `ThreadPoolExecutor`，根据任务类型设置 core/max pool size、keepAlive、有界队列、带业务名的 ThreadFactory 和拒绝策略；提交任务后还要捕获异常、监控 active count、queue size 和拒绝次数，并在服务关闭时先 `shutdown`、超时后再 `shutdownNow`。这样才能控制过载，而不是只会调用 `Executors.newFixedThreadPool`。

##### 知识点补充

线程池核心参数包括 core/max pool size、keepAlive、workQueue、threadFactory 和 rejectedExecutionHandler。无界队列可能隐藏过载并最终 OOM；`Executors` 的便捷工厂在生产上也要警惕无界队列或无界线程数。

##### 二叉树遍历与路径问题

Q：二叉树如何按层打印、验证搜索树，并找出根到叶子节点和为目标值的路径？
A：按层打印我会用队列：根节点入队，每轮先记录当前队列长度，正好处理这一层并把左右孩子入队，时间 `O(n)`。验证搜索树不能只比较父子节点，我会递归传递合法区间，左子树上界是当前值、右子树下界是当前值，并用 `long` 防止整数边界溢出；若允许重复值还要先约定重复放哪一侧。路径和则用 DFS 维护剩余值和当前路径，只在叶子节点判断剩余值是否等于节点值，命中后复制路径，回溯时删除尾节点。线上代码会优先写迭代层序，深度可能很大时把递归 DFS 改成显式栈，避免栈溢出。

##### 知识点补充

完全二叉树若用从 0 开始的数组编号，节点 `i` 的父节点是 `(i-1)/2`，左右孩子是 `2i+1`、`2i+2`；从 1 开始编号时父节点是 `i/2`。

##### LRU 缓存实现

Q：如何设计一个查询和更新都是 `O(1)` 的 LRU 缓存？
A：我会用 HashMap 加双向链表。Map 从 key 定位节点，链表头表示最近使用、尾部表示最久未使用；get 命中后把节点摘下并移动到头部，put 已存在就更新值并移到头部，不存在则在头部插入，超过容量时删除尾节点并同步移除 Map。实现时使用虚拟 head、tail 能统一首尾操作，每次移动都要同时维护四个相邻指针。若用于生产缓存，我还会说明这份基础实现不是线程安全的；并发场景要加锁或使用成熟缓存库，同时考虑过期时间、容量按条数还是内存计算、加载失败和命中率监控。

##### 知识点补充

LinkedHashMap 可以通过访问顺序和 `removeEldestEntry` 快速实现单机 LRU，但面试手写 HashMap 加双向链表更能说明不变量。分布式缓存淘汰还会涉及近似 LRU，而非严格链表顺序。

##### Java 多态与动态绑定

Q：Java 多态是什么，实际开发中怎么使用？
A：多态的核心是“父类型引用指向子类对象，调用被重写的实例方法时按运行时类型分派”。例如支付接口定义 `pay()`，微信和银行卡分别实现，业务编排只依赖 `Payment`，新增渠道时不需要修改主流程。我会同时说明：成员变量和静态方法不参与这种动态绑定，重载在编译期根据声明类型和参数决定，重写才是运行期分派；向下转型前要保证真实类型，避免 `ClassCastException`。实际项目中我更常配合接口、策略模式和依赖注入使用多态，但不会为了形式把只有一个实现、不会变化的逻辑过度抽象。

##### 知识点补充

重写要求方法签名兼容，返回值可协变，访问权限不能更严格；`final`、`private` 方法不能被正常重写。构造器中调用可重写方法可能访问尚未初始化的子类状态，应避免。

##### 随机红包算法

Q：如何实现随机发红包，并保证金额不超发、每个人至少拿到一分钱？
A：金额统一转换为“分”用整数计算，避免浮点误差。常见做法是二倍均值法：剩余金额 `remain`、剩余人数 `n` 时，本次在 `[1, 2×remain/n-1]` 内随机，发完后同步扣减；最后一人拿走全部余额。比如 1000 分发给 10 人，每轮上限会随余额变化，能避免前面拿太多导致后面不足。实现时我会校验 `total >= n`、随机上界至少为 1，并在测试中验证总和不变、每份大于等于 1。若业务要求严格均匀或可审计，我会使用预切分点或服务端保存随机种子，并处理并发抢红包的原子扣减与幂等。

##### 知识点补充

二倍均值法只是常用分布，不等于每种拆分方案等概率。高并发领取通常先生成红包明细，再用 Redis Lua、库存队列或数据库条件更新保证一份只被领取一次。

##### 链表相交、倒数节点与环入口

Q：如何一次遍历解决链表相交、倒数第 N 个节点和环入口问题？
A：两条无环链表求相交节点，我用两个指针分别从 A、B 出发，到尾后切换到另一条链，走过 `lenA+lenB` 后会在首个公共节点相遇；比较的是节点引用，不是值。求倒数第 N 个节点时让 fast 先走 N 步，再让 fast、slow 同速前进，fast 到尾时 slow 即为答案，并明确 N 非法时返回什么。环入口用 Floyd：快慢指针首次相遇后，把一个指针放回头节点，两者每次走一步，再次相遇处就是入口。实际编码会先处理空链、N 大于长度，并确认相交链表是否可能带环，因为带环时需要进一步分类讨论。

##### 知识点补充

这些题都依赖指针路程关系，额外空间是 `O(1)`。若允许哈希集合，环检测和相交也能直观实现，但空间会变成 `O(n)`。

##### 有序数组归并与归并排序

Q：如何合并两个或 K 个有序数组？归并排序的实现要点是什么？
A：两个数组合并用双指针，每次取较小值，某一侧耗尽后追加另一侧；若结果写回第一个且尾部容量足够，应从后向前比较，避免覆盖未处理元素。K 个有序数组我会用最小堆保存每个数组当前元素和来源下标，每弹出一个就推进对应数组，复杂度 `O(N log K)`；也可以两两分治归并。归并排序先递归拆半，再用临时数组稳定合并，时间始终 `O(n log n)`、额外空间 `O(n)`。工程上会注意中点防溢出、空数组、重复值稳定性，并根据数据规模决定是否对小区间切换插入排序。

##### 知识点补充

外部排序也是归并思想：内存中分块排序写临时文件，再做多路归并。K 很大时堆的大小和同时打开的文件数都需要限制。

##### 第 K 小与矩阵搜索

Q：有序矩阵中如何搜索目标值或找到第 K 小元素？
A：若矩阵每行、每列都递增，搜索目标从右上角开始：当前值大于目标就左移，小于目标就下移，每步排除一行或一列，复杂度 `O(m+n)`。求第 K 小可对“值域”二分，给定 mid 时从左下角线性统计小于等于 mid 的元素个数；若数量小于 K，左边界设为 `mid+1`，否则收缩右边界，最终得到答案，复杂度 `O((m+n)log(valueRange))`。如果只有每行有序、列无序，我会改用 K 路最小堆，不能错误套用右上角搜索。

##### 知识点补充

值域二分寻找的是满足“元素个数至少为 K”的最小值，因此即使矩阵有重复值也成立。矩阵为空、K 越界应在入口校验。

##### 最大子数组和与字典序第 K 个数

Q：最大连续子数组和怎么求？1 到 n 中按字典序排列的第 K 个数怎么找？
A：最大子数组和用 Kadane：`current=max(nums[i], current+nums[i])`，同时更新全局最大值；初值必须来自第一个元素，才能正确处理全负数组，时间 `O(n)`、空间 `O(1)`。字典序第 K 个数则把数字看成十叉前缀树，用 `countSteps(prefix,prefix+1,n)` 计算某前缀下有多少节点；若子树规模不超过剩余 K，就跳到下一个兄弟前缀，否则进入当前前缀的下一层。这样不会真的生成 1 到 n，复杂度大约 `O(log²n)`。实现计数时使用 `long`，防止 `prefix*10` 溢出。

##### 知识点补充

Kadane 还可以记录最佳区间的起止下标。字典序算法通常先令 `current=1`、`k--`，因为第一个节点已经占用一个名次。

##### 海量数据 TopK 与频次统计

Q：一百万个数或多个 1GB 文件放不进内存，如何求 Top100 或查询频次排序？
A：只求数值 Top100 时流式读取，用容量 100 的最小堆；新值大于堆顶才替换，内存 `O(100)`、时间 `O(n log100)`。若要统计关键词频次，不能直接对原记录建堆，我会先按 `hash(key)%P` 分桶，保证相同 key 进入同一小文件；逐桶用 HashMap 聚合频次，再维护全局 TopK，最后合并各桶候选。如果单桶仍过大就增加桶数或递归分桶。实际执行还会处理压缩输入、临时磁盘容量、文件句柄、哈希倾斜、失败重跑和中间文件清理；分布式环境可直接用 MapReduce/Spark 完成分区聚合和二阶段 TopK。

##### 知识点补充

“分桶”适合聚合同 key，“外排序+多路归并”适合需要完整全局排序。只求 TopK 不应把全部数据排序，除非后续还要复用完整有序结果。

##### JVM 运行时内存、OOM 与锁

Q：JVM 的栈、堆和方法区如何区分？OOM 与 Java 锁问题怎么排查？
A：堆保存对象实例并由 GC 管理；每个线程有独立虚拟机栈，栈帧保存局部变量、操作数栈和返回信息；方法区规范在 HotSpot 中主要由 Metaspace 实现，保存类元数据，直接内存则常被 NIO 和框架使用。线上 OOM 我先看异常类型和容器是否被系统杀死：堆 OOM 开启 dump 查 dominator tree，Metaspace 看动态类加载，direct buffer 看堆外指标，线程创建失败看线程数和栈大小。锁问题则通过 thread dump 找 BLOCKED、死锁和持锁链，结合 JFR/async-profiler 看竞争热点；修复时缩小临界区、统一加锁顺序，读多写少可评估读写锁，但不会盲目换并发工具。

##### 知识点补充

`synchronized` 保证互斥和可见性，`ReentrantLock` 提供可中断、超时、公平锁和多个 Condition。CAS 适合短临界区，高竞争下自旋会浪费 CPU，还要考虑 ABA 问题。

##### 一致性哈希与布隆过滤器

Q：一致性哈希和布隆过滤器分别解决什么问题，落地时有哪些限制？
A：一致性哈希把节点和 key 映射到同一个哈希环，key 顺时针落到第一个节点；扩缩容时主要影响相邻区间，减少普通取模导致的大规模迁移。实际会给每个物理节点配置多个虚拟节点，改善数据均衡，并结合节点权重、故障摘除和副本策略。布隆过滤器用多个哈希函数设置位数组，查询为“任一位为 0 则一定不存在，全部为 1 则可能存在”，适合缓存穿透拦截和大集合预判。它有误判、通常不能直接删除，因此不能把“可能存在”当成最终结果；容量增长后要重建或使用可扩展/计数型布隆过滤器。

##### 知识点补充

布隆过滤器位数组大小和哈希函数数量取决于预计元素量与目标误判率。Redis Cluster 自身使用哈希槽，不等同于一致性哈希，回答时要区分具体系统实现。

##### 25 匹马赛跑问题

Q：25 匹马、5 条赛道、没有计时器，最少几场找出最快的 3 匹？
A：先分 5 组各跑一场得到组内排序，共 5 场；再让 5 个小组第一名跑第 6 场，假设结果为 A1>B1>C1>D1>E1。根据淘汰关系，前三只可能只在 A1、A2、A3、B1、B2、C1 中；A1 已确定总第一，因此第 7 场只需要让 A2、A3、B1、B2、C1 比赛，前两名与 A1 组成总前三。所以最少 7 场。回答时我会把候选集合如何缩小讲清楚，而不是只报“7 场”；例如 D、E 组所有马至少已有三匹明确比它们快，B3、C2 之后同理不可能进入前三。

##### 知识点补充

这题默认每场能明确排出 5 匹先后且没有并列。核心是利用偏序关系淘汰不可能候选，不是计算速度。

##### 辛普森悖论与数据分析校验

Q：什么是辛普森悖论，业务分析中如何避免错误结论？
A：辛普森悖论指各分组中的趋势一致，但合并后因组别权重不同而反转。例如渠道 A、B 内新版转化率都更高，但新版流量更多落在低转化渠道，汇总后反而看起来更差。实际分析我会先确认随机分流和样本结构，按渠道、地区、新老用户等潜在混杂变量分层，同时给出各层样本量、转化率和加权口径；若要判断因果，优先依赖随机实验，观察数据则使用回归、倾向得分等方法控制混杂。结论会上明确“分层结果”和“总体业务结果”分别回答什么问题，不会挑一个对自己有利的数字。

##### 知识点补充

它不是数据错误，而是聚合权重改变带来的统计现象。选择分层变量应基于业务机制和实验设计，不能事后无限切片制造显著性。

##### ConcurrentHashMap、HashSet 与线程安全

Q：HashMap 为什么线程不安全？还有哪些 Map 实现，HashSet 如何去重？
A：HashMap 并发 put、扩容和复合读改写没有同步，可能丢更新或读到不一致状态，不能用 `volatile HashMap` 修复。并发场景通常使用 ConcurrentHashMap，它在 JDK 8 中通过桶级 CAS 和 synchronized 控制更新，读取大多无锁；需要有序可用 TreeMap，保持插入/访问顺序用 LinkedHashMap，枚举键可用 EnumMap。HashSet 底层以 HashMap 的 key 存元素，add 时先算 hash 定位桶，再用 equals 判断是否已经存在，因此自定义对象必须同时正确实现 hashCode/equals，且入集合后不要修改参与哈希的字段。跨多步原子逻辑要使用 compute/merge 或额外锁，不能因容器并发安全就认为业务操作原子。

##### 知识点补充

ConcurrentHashMap 不允许 null key/value，避免并发下无法区分“没有映射”和“映射为 null”。CopyOnWriteMap 并非 JDK 常规通用实现，读写模型要根据场景选择。

##### JDBC 查询流程与资源关闭

Q：以 SELECT 为例说明 JDBC 完整流程和资源关闭顺序。
A：我会从连接池获取 Connection，用 PreparedStatement 写带占位符 SQL 并绑定参数，设置查询超时和合理 fetch size，执行 `executeQuery` 得到 ResultSet，逐行映射业务对象。PreparedStatement 不只是防 SQL 注入，也便于类型绑定和计划复用。资源按创建的反序关闭：ResultSet、Statement、Connection；实际用 try-with-resources 自动关闭，即使映射异常也会归还连接池。事务查询需要明确 autoCommit、隔离级别和只读属性，异常时回滚。线上还会监控连接池 active/idle、等待时间、慢 SQL 和未关闭连接，禁止循环内为每行新建连接或拼接用户输入。

##### 知识点补充

关闭池化 Connection 通常是归还池而非物理断开。驱动、连接池和数据库对 fetch size 的行为可能不同，需要实测大结果集是否流式拉取。

##### Spring Boot、MyBatis 与工程分层

Q：项目中怎样使用 Spring Boot 和 MyBatis，它们分别解决什么问题？
A：Spring Boot 用自动配置、Starter 和配置管理快速组装 Web、监控、连接池等基础设施，业务上我会按 Controller、Service、Repository/Mapper 分层：Controller 做协议校验，Service 管事务和业务规则，Mapper 只负责 SQL。MyBatis 适合需要精细控制 SQL 的查询，通过 Mapper 接口、XML/注解映射参数与结果；动态 SQL 必须使用参数绑定，表名等无法绑定的标识符采用白名单。批量写使用 foreach 和合理批次，分页避免深 offset，慢 SQL通过执行计划和索引优化。配置按环境外置，敏感信息走密钥系统，并用 Actuator、日志 trace id 和连接池指标监控。

##### 知识点补充

Spring Boot 是应用装配框架，MyBatis 是持久层映射工具。`@Transactional` 依赖代理，自调用、异常被吞或非 public 边界可能导致事务不生效。

##### Maven 与 Gradle 构建管理

Q：Maven 和 Gradle 是什么，项目中如何管理依赖和构建？
A：二者都负责依赖解析、编译、测试、打包和发布。Maven 使用声明式 POM 和固定生命周期，规范统一、生态成熟；Gradle 使用 Groovy/Kotlin DSL，任务图灵活，支持增量构建和构建缓存。实际项目我会锁定 JDK 与插件版本，通过 dependency management/version catalog 统一依赖，检查 dependency tree 解决传递依赖冲突，并区分 compile/runtime/test 范围。大数据 fat jar 还要把 Spark/Flink 集群已有依赖设为 provided，第三方冲突用 shade/relocate，最终在 CI 执行测试、漏洞扫描和可重复构建，不能只在本机打包成功。

##### 知识点补充

依赖版本“最近者优先”等规则可能隐藏冲突，应显式管理核心版本。Gradle 灵活不代表脚本越复杂越好，构建逻辑也要模块化和可测试。

##### String、StringBuilder 与 StringBuffer

Q：StringBuilder 和 StringBuffer 有什么区别，字符串拼接怎么选择？
A：String 不可变，每次循环用 `+` 可能创建大量临时对象；编译器能优化单条常量或简单表达式，但不能保证优化动态循环。StringBuilder 使用可扩容字符数组，方法不同步，单线程局部拼接优先使用；StringBuffer 的主要方法带 synchronized，线程安全但有同步开销。实际不会让多个线程共享同一个可变 builder，而是每个线程独立构建后合并；真正共享结果应使用并发容器或明确锁。容量可按预计长度初始化，最终调用 toString；拼 SQL 则仍应使用参数化查询，不能因为 builder 高效就手拼用户输入。

##### 知识点补充

JDK 9 后 String 内部实现发生过变化，但不可变语义不变。是否产生临时对象应以字节码/JFR 实测，不背绝对结论。

##### Unix 路径化简

Q：如何把 `/a/./b/../../c/` 化简为规范 Unix 路径？
A：按 `/` 切分后用栈处理：空段和 `.` 忽略；遇到 `..` 且栈非空就弹出一级，栈空时保持根目录；普通目录名入栈。最后用 `/` 连接栈内容并补前导斜杠，栈空返回 `/`。示例依次处理 a、b，两个 `..` 分别弹出 b、a，最后压入 c，得到 `/c`。时间和空间都是 `O(n)`。编码时不会用文件系统真实解析，避免受当前目录和符号链接影响；题目是词法规范化，目录名中的多个点如 `...` 仍是普通名称。

##### 知识点补充

若题目允许相对路径，栈空时的 `..` 不能直接丢弃，规则与绝对路径不同。连续斜杠通过跳过空段自然合并。

##### 最长公共前缀与 URL 解析

Q：如何求字符串数组最长公共前缀？业务代码中如何安全拆解 URL？
A：最长公共前缀我先取第一个字符串为候选，逐个与后续字符串比较并缩短到公共部分，一旦为空立即返回；总复杂度不超过所有字符总数，空数组和空字符串单独处理。也可纵向按列比较，但要先检查每个字符串长度。URL 不能简单按 `/` 或 `?` 多次 split，我会使用 `java.net.URI` 解析 scheme、host、port、path、query、fragment，再对 query 按规则解码；路径中的 `%2F`、`+`、空参数和重复 key 都需要明确语义。若输入可能是不完整 URL，先校验并返回结构化错误，不把异常地址静默拼成合法值。

##### 知识点补充

最长公共前缀是字符比较问题；URL 是有语法和编码规则的协议标识，两者不应共用粗暴字符串切割方案。

##### 复原 IP 地址回溯

Q：只包含数字的字符串，如何返回所有合法 IPv4 地址？
A：用回溯切出恰好 4 段，每段长度 1—3。递归参数包含当前位置和已选段数；剪枝时若剩余字符少于剩余段数或多于其三倍，直接返回。候选段若长度大于 1 且首字符为 0 不合法，解析值超过 255 也停止继续扩长。选满 4 段且刚好用完整个字符串时，用点连接加入结果。例如 `25525522135` 会得到 `255.255.22.135` 和 `255.255.221.35`。由于最多尝试有限切点，实际复杂度很小；输入长度不在 4—12 直接返回空。

##### 知识点补充

`0` 合法但 `00`、`01` 不合法。回溯保存结果时要复制当前段列表，不能保存同一个可变引用。

##### 子集回溯

Q：如何求一个不含重复元素的整数集合的所有子集？
A：我用回溯维护当前路径和起始下标。每进入一层就先复制当前路径加入结果，因为空集和每个中间路径本身都是合法子集；然后从 start 开始选择元素，加入后递归 `i+1`，返回时删除尾元素。输入 `[1,2,3]` 会依次得到空集、单元素、双元素和全集，共 `2^n` 个。时间复杂度 `O(n×2^n)`，空间除结果外是 `O(n)` 递归深度。如果输入允许重复值，需要先排序并跳过同层相同元素；本题已明确不重复，就不额外引入去重集合。

##### 知识点补充

全排列每层从所有未使用元素中选，子集/组合只向后选择，这是两类回溯模板的关键区别。保存结果必须复制路径。

##### 冒泡排序与快速排序

Q：手写冒泡排序和快速排序，并说明边界、复杂度与适用场景。
A：冒泡每轮比较相邻元素并交换，把当前最大值推到右端；若一轮没有交换可提前结束，平均和最坏 `O(n²)`、最好 `O(n)`，稳定且可原地，但只适合教学或小数据。快速排序选择 pivot，把区间划分为小于和大于 pivot 的两侧再递归；我会随机选 pivot 或三数取中，避免有序输入导致 `O(n²)`，分区时明确使用 Hoare 或 Lomuto 模板并处理重复值。平均 `O(n log n)`、递归栈平均 `O(log n)`，不是稳定排序。生产 Java 对对象和基本类型有成熟排序实现，除面试手写外不重复造轮子。

##### 知识点补充

快速排序的正确性取决于分区不变量和递归边界。重复值很多时三路划分能显著减少无效递归；递归过深可改用显式栈或 introsort。

##### 第 K 大元素

Q：无序数组中如何找到第 K 大元素？
A：我优先用 Quickselect。把“第 K 大”转换为升序下标 `n-k`，随机选 pivot 分区；若 pivot 最终位置等于目标就返回，小于目标只递归右侧，否则递归左侧。平均时间 `O(n)`、额外空间可做到 `O(1)`，最坏 `O(n²)`，随机化能降低退化概率。若数据流持续到来或要反复查询 TopK，则维护容量 K 的最小堆，时间 `O(n log k)`；如果 K 越界、数组为空要明确报错。存在重复值时第 K 大按排序后位置计算，不误当成第 K 个不同值。

##### 知识点补充

Quickselect 只保证目标位置正确，不会把整个数组排好序。需要稳定返回原下标或第 K 个不同值时，接口和算法都要调整。

##### 两数之和与只出现一次的数字

Q：如何在线性时间内解决“两数之和”和“其他数出现两次、只有一个数出现一次”？
A：两数之和单次遍历，用 HashMap 保存“值→下标”；访问 `nums[i]` 时先查 `target-nums[i]`，命中就返回旧下标和 i，再写入当前值，避免同一个元素使用两次，时间和空间都是 `O(n)`。如果数组已排序可用双指针，但原始下标要额外保留。只出现一次的数字利用异或：`x^x=0`、`x^0=x` 且满足交换律，把所有元素异或后就是单一值，时间 `O(n)`、空间 `O(1)`。异或方法只适用于其余元素恰好成对的前提，出现三次或有两个单值要换位运算方案。

##### 知识点补充

两数之和遇到重复值时先查后放可正确处理 `[3,3]`。整数加减若可能溢出，应使用 long 或明确输入范围。

##### 两个栈实现队列

Q：如何用两个栈实现队列，并保证摊销复杂度合理？
A：维护输入栈 in 和输出栈 out。入队只压入 in；出队或查看队首时，如果 out 非空直接取，只有 out 为空才把 in 全部弹出并压入 out，元素顺序因此反转成先进先出。不能每次出队都来回搬，否则复杂度退化。每个元素最多进入、离开两个栈各一次，所以入队和出队摊销都是 `O(1)`，最坏某次出队是 `O(n)`。实现时处理空队列异常，并明确 peek 不删除。并发使用时还需整体锁住“检查 out 并搬移”的复合操作。

##### 知识点补充

摊销分析不代表每次操作都常数时间，而是长序列平均成本。两个队列实现栈与本题方向相反，不要混用模板。

##### 会话划分算法

Q：日志包含 uid、url、datetime，连续访问间隔不超过 5 分钟算同一会话，如何生成 session_id？
A：离线处理先按 uid 分组、datetime 升序；每个用户第一条开启新会话，后续记录与上一条有效访问时间比较，差值大于 5 分钟就把会话序号加一，否则沿用。session_id 可由 `uid + 会话首条时间 + 序号` 稳定生成，不能用随机 UUID 导致重跑不一致。Java 流式扫描时维护每个 uid 的 lastTime、sessionStart 和 seq；数据未排序则必须先排序或在事件时间流中用 Watermark、状态和定时器等待乱序。重复事件先按 event_id 去重，非法时间进入侧路，最终用样例验证恰好 5 分钟是否仍属同会话。

##### 知识点补充

SQL 可用 `lag` 比较上一条时间，再对“新会话标记”做累计 sum。会话超时是业务参数，跨天是否延续也需明确。

##### 数组排序后原地去重

Q：不能使用 Stream API，如何对整数数组排序并去重？
A：先用原地排序把相同值放到一起，再用快慢指针压缩。数组为空直接返回；slow 指向当前唯一序列末尾，fast 从 1 开始扫描，若 `a[fast] != a[slow]`，就递增 slow 并把 fast 值写到 `a[slow]`。最终有效长度是 `slow+1`，前缀即去重结果。若题目要求保留原始出现顺序，就不能先排序，应使用 LinkedHashSet 或哈希集合加新数组。面试时我会先确认返回新数组还是有效长度，因为 Java 数组长度固定，所谓原地去重只能覆盖前缀。

##### 知识点补充

排序加去重时间 `O(n log n)`；若不要求顺序，哈希去重平均 `O(n)` 但需额外空间。基本类型数组和对象数组的排序实现不同。

##### 红黑树为什么用于 HashMap

Q：HashMap 为什么在冲突严重时把链表转换成红黑树？红黑树如何保证查询性能？
A：链表查找最坏是 O(n)，大量 key 落到一个桶时会明显变慢；红黑树通过近似平衡把查找、插入和删除的最坏复杂度控制在 O(log n)。Java 8 中桶内节点数达到 8 且数组容量至少 64 才树化，容量不足时优先扩容，因为冲突可能只是容量太小；节点数降到 6 左右会退回链表，避免小数据量承担树节点的额外开销。实际排查时我还会检查 key 的 hashCode 分布，以及 equals/hashCode 是否满足一致性，不能靠树化掩盖错误实现。

##### 知识点补充

红黑树不追求绝对平衡，而是保证最长路径不超过最短路径的两倍，在更新成本和查询上界之间折中。

##### CMS 与 G1 的选择和排障

Q：CMS 和 G1 有什么差异？生产环境出现频繁 GC 时你怎么处理？
A：CMS 面向老年代并发回收，停顿较短，但会产生碎片，还可能发生 Concurrent Mode Failure；G1 把堆划成 Region，按回收收益选择区域，并用停顿目标控制节奏，更适合大堆。频繁 GC 时我先从 GC 日志区分 Young、Mixed 还是 Full GC，再看分配速率、对象晋升、老年代占用和暂停分位数；随后用堆转储定位大对象、缓存或泄漏，而不是先调大堆。晋升过快就检查对象生命周期和 Survivor，Humongous 对象多就缩小超大数组或批次，分配过快则减少临时对象并校准并发度。

##### 知识点补充

CMS 典型阶段是初始标记、并发标记、重新标记、并发清除；G1 包含 Young GC、并发标记和 Mixed GC。调优要同时看吞吐量、暂停分位数、堆趋势和 Full GC 次数。

##### BFS、DFS 与图遍历

Q：BFS 和 DFS 分别适合什么场景？怎样避免重复访问或栈溢出？
A：无权图最短路径和层级遍历我用 BFS，节点入队时就标记 visited，防止重复入队；连通性、回溯枚举和深度探索更适合 DFS。图很深时我用显式栈替代递归，避免线程栈溢出。编码前先确认有向或无向、是否有环，并按节点唯一标识维护 visited；两者时间复杂度通常都是 O(V+E)，空间分别受最大层宽和搜索深度影响。

##### 知识点补充

多源最短距离可把所有源点一起入队。普通 BFS 只适合无权或等权边；非负权重通常用 Dijkstra，不能直接套 BFS。

##### 分割数组最大和最小

Q：把数组分成 m 个连续子数组，怎样让各段和的最大值最小？
A：我会二分答案。下界是最大元素，上界是数组总和；给定 mid，从左到右贪心累加，超过 mid 就切新段，得到满足该上限所需的最少段数。段数大于 m 说明 mid 太小，否则继续压低上限，最终边界相遇就是答案，复杂度 O(n log(sum-max))。累加使用 long，并先确认元素非负，因为有负数时可行性不再单调。

##### 知识点补充

这是二分答案的关键：答案范围可界定，且“上限为 x 是否可行”具有单调性。非负数组若能分成不超过 m 段，还可以继续拆到恰好 m 段。

##### 最长回文子串

Q：如何求字符串的最长回文子串？你会怎样选择实现？
A：现场我通常写中心扩展：每个字符作为奇数中心，每个相邻间隙作为偶数中心，向两侧扩展并更新最长区间。它是 O(n²) 时间、O(1) 空间，代码短且容易验证。数据特别长且明确要求线性复杂度时才用 Manacher；若还要输出多个区间，也可用动态规划。实现只保存 start 和 maxLen，最后截取一次字符串，避免循环中反复创建对象。

##### 知识点补充

中心扩展必须同时处理 `(i,i)` 和 `(i,i+1)`。Manacher 用分隔符统一奇偶回文，并利用最右边界及镜像半径达到 O(n)。

##### 合并两个有序链表

Q：怎样合并两个有序链表？如何处理空链表和剩余节点？
A：我用 dummy 头节点和 tail 尾指针；两个游标比较当前值，把较小节点直接接到 tail 后并前移，某条链表耗尽后把另一条剩余部分整体接上。这样复用原节点，时间 O(m+n)、额外空间 O(1)。若要求不修改输入链表才复制节点；若输入可能相交，还需避免把共享尾部重复连接成环。

##### 知识点补充

dummy 能统一首节点与后续节点处理。递归写法更短，但深度可达 m+n，长链表在生产中更适合迭代。

##### Scala foreach 累加失效

Q：为什么在 Spark 的 foreach 里给普通变量累加，Driver 最后仍然是原值？
A：算子闭包会被序列化到 Executor，每个 Task 修改的是自己的变量副本，结果不会自动回到 Driver。精确统计应使用 count、reduce、aggregate 或 DataFrame 聚合；只有诊断计数才使用 LongAccumulator，而且 Task 重试可能重复累加，所以不能把它当业务结果。业务输出应沿数据流聚合后返回，或写入支持幂等的下游。

##### 知识点补充

广播变量用于 Driver 向 Executor 分发只读数据，累加器用于汇总附加指标；Transformation 惰性执行，没有 Action 时其中的累加逻辑不会运行。

##### TreeSet 与 HashSet

Q：TreeSet 和 HashSet 有什么区别，实际如何选择？
A：只需要去重和快速判断存在时我用 HashSet，它基于 HashMap，平均插入、查询是 O(1)，但不保证遍历顺序；需要自动排序、范围查询或找相邻元素时用 TreeSet，它基于红黑树，操作是 O(log n)。TreeSet 的元素必须能比较，可实现 Comparable 或传 Comparator，而且比较结果为 0 就会被视为同一元素，即使 equals 不同。HashSet 则要求 equals 与 hashCode 一致。若既要保留插入顺序又要去重，我选择 LinkedHashSet，而不是误用 TreeSet。

##### 知识点补充

向 TreeSet 放入比较规则不一致的对象可能丢数据；可变字段参与 hash 或比较后再修改，也会破坏集合定位，应使用不可变键。

##### Spring Boot 常用注解与职责

Q：Spring Boot 项目中常用哪些注解？你实际怎样组织一个服务模块？
A：启动类用 `@SpringBootApplication`，它组合了配置、自动配置和组件扫描；接口层用 `@RestController`、`@RequestMapping`，参数按来源使用 `@PathVariable`、`@RequestParam`、`@RequestBody` 并配合 `@Valid`。业务类用 `@Service`，数据访问用 `@Repository` 或 Mapper，依赖通过构造器注入；配置项用 `@ConfigurationProperties` 映射，事务放在公开业务方法的 `@Transactional` 上。实际模块会按 controller、service、repository、domain/config 分层，统一异常处理、日志 traceId、参数校验和接口测试，不把 SQL、事务和返回拼装全塞进 Controller。

##### 知识点补充

同类内部直接调用带 `@Transactional` 的方法可能绕过代理；事务边界、回滚异常和传播级别要结合实际调用链验证。构造器注入更利于测试和发现循环依赖。

##### 线程池与连接池

Q：线程池和数据库连接池分别解决什么问题？参数怎样设置？
A：线程池复用线程并限制并发，避免请求高峰无限创建线程；连接池复用昂贵的数据库连接并限制对下游的并发。线程池我会显式配置 core/max、队列、keepAlive、线程名和拒绝策略，依据任务是 CPU 密集还是 I/O 密集压测，不直接使用无界队列；异步调用外部接口还要设超时、隔离池和熔断。连接池设置最大/最小连接、获取超时、空闲检测和连接存活时间，最大值受数据库承载而不是应用线程数决定。两者都监控活跃数、队列、等待时间、拒绝/超时和泄漏。

##### 知识点补充

线程池过大增加上下文切换，连接池过大可能压垮数据库。批量事务要限制单批大小，失败重试必须有上限并保证幂等。

##### Java 定时任务选型

Q：Java 中怎样实现定时任务？Timer、ScheduledExecutorService 和调度平台怎么选？
A：进程内简单周期任务我用 ScheduledExecutorService，支持多线程、异常隔离和固定频率/固定延迟调度；不用单线程 Timer 承载核心任务，因为一个任务阻塞会拖延后续，未捕获异常还可能终止调度线程。分布式、需补跑和审计的生产任务交给 DolphinScheduler、XXL-JOB 等平台，并用分布式锁或分片保证同一计划不会重复执行。无论哪种方式，任务都要有稳定执行日期、幂等写入、超时和告警，重启后如何补偿不能依赖内存计时器。

##### 知识点补充

固定频率会尝试维持计划节奏，固定延迟从上次完成后再等待。系统时钟、时区和夏令时会影响 cron，业务日期应显式传入。

##### JVM 现场诊断命令

Q：线上 Java 进程 CPU 高、内存高或线程卡住，你会用哪些命令定位？
A：我先用 top/ps 找到进程和高 CPU 线程，再把线程 ID 转十六进制，用 `jstack` 对应线程栈；连续抓取多次，判断是死循环、锁等待还是 GC 线程。内存问题先用 `jstat -gcutil` 看代际和 GC 趋势，用 `jcmd GC.class_histogram` 看对象分布，必要时通过 `jcmd GC.heap_dump` 生成堆文件并离线用 MAT 分析。类加载、JVM 参数可用 `jcmd VM.flags`、`VM.system_properties` 查看。生产执行堆转储前先评估磁盘和停顿，工具版本要与目标 JVM 匹配。

##### 知识点补充

一次快照只能说明当时状态，趋势更重要。不要在故障现场频繁 Full GC 或连续 dump；先保存证据，再做限流、摘流或重启。

##### 单例模式的正确实现

Q：项目中为什么使用单例模式？并发下如何避免写出不安全的单例？
A：只有对象确实无状态、创建成本高或代表唯一资源协调器时我才用单例，例如配置解析器；数据库连接本身不做单例，而交给连接池。Spring Bean 默认已是容器级单例，不需要再手写静态实例。必须手写时可用枚举或静态内部类，既保证懒加载又利用类初始化的线程安全；双重检查则实例必须声明 volatile，防止指令重排暴露半初始化对象。单例中不能随意保存请求级可变字段，否则多个线程会串数据。

##### 知识点补充

单例只保证一个 JVM 内唯一，分布式部署下每个进程都有实例；跨节点唯一性要用数据库约束、租约或分布式锁实现。

##### Java 按任务和小时聚合

Q：给定 task 和时间字段，怎样用 Java 统计每个任务每小时的点击数？
A：我先把时间字符串用预先创建的 DateTimeFormatter 解析成 LocalDateTime，取日期和小时，和 task 组成不可变复合键；遍历数据时用 `Map<Key, Long>` 的 `merge(key,1L,Long::sum)` 累加。输出前按 task、日期、小时排序，格式化为稳定结果。解析失败不能直接吞掉，要记录原始行和原因；若数据跨时区，先按业务 ZoneId 归一化。数据量超过单机内存时不会硬塞 HashMap，而是用 Spark/Flink 按相同复合键分区聚合。

##### 知识点补充

SimpleDateFormat 非线程安全，Java 8 的 DateTimeFormatter 是不可变的。只按小时不带日期会把多天相同小时错误合并。

##### Scala 核心语言特性

Q：Scala 的 val/var、闭包和模式匹配怎样理解，在 Spark 开发中如何使用？
A：`val` 绑定不可重新赋值，`var` 可以修改；业务代码我优先 val 和不可变集合，降低分布式闭包中的共享状态风险。闭包是函数连同其引用的外部变量，Spark 会把闭包序列化到 Executor，所以不能捕获不可序列化连接，也不能期望修改 Driver 普通变量。模式匹配可按值、类型、case class 解构并配合守卫处理不同事件，比连续 if 更清晰，但必须覆盖默认分支。case class 常用于不可变数据模型，不过大对象和嵌套集合仍要关注序列化成本。

##### 知识点补充

Scala 的高阶函数、Option、集合变换提高表达力，但生产代码仍需控制隐式转换、空值和闭包大小，不能为了语法简短牺牲可读性。
