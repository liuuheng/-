# Flink最长连续日期：去重、合并与状态边界

对应代码：[FlinkConsecutiveDays.java](FlinkConsecutiveDays.java)。适用版本：Flink 2.3.0 / Java 17。本篇解释同目录这一份实现，保留与 Hive 案例一致的业务规则，并明确引擎接口上的变化。

## 结果是去重后的最长自然日连续段

输入严格的八位 `uuuuMMdd` 日期字符串，输出 `INT`。例如 `20261001,20261002,20261002,20261004` 的最长连续段为 `2`；重复日期不能把连续长度增加到 `3`。空值、非八位文本和非法日历日期忽略，无有效日期时返回 `0`。

使用 `ResolverStyle.STRICT` 拒绝 `20260230`；使用 `uuuu` 表示可严格解析的年份。`LocalDate.toEpochDay()` 将自然日转成整数，跨月、跨年也只需判断两个值是否相差 1，不经由时区时间戳，不用固定毫秒数模拟一天。

## 为什么不能只保存局部最长长度

一个分区可能有 `01,02`，另一个有 `03,04`；两个分区的局部最长长度都是 2，合并后的答案却是 4。只传递局部最大值会丢失边界能否连接的信息。本例保留日期级状态，在分区合并后重新判断连续关系。

取值时对有效日期排序，维护 `previous`、`current` 和 `longest`：当前日等于前一日加 1 则延长当前段，否则从 1 重新开始。排序后的每个有效日期只扫描一次。

## 状态大小的边界

若一组内有 `d` 个不同有效日期，日期级状态至少随 `d` 增长，本实现取值需要约 `O(d log d)` 的排序时间和 `O(d)` 临时空间。它没有把精确的无限历史统计变成固定内存算法。应先定义按用户、窗口或业务周期保留哪些日期，再选择状态生命周期；随意清理仍可能改变最长连续段。

## Flink 必须保存日期出现次数

类继承 `AggregateFunction<Integer,Accumulator>`，状态是 `Map<Long,Long>`，记录 `epochDay → 次数`。`accumulate` 对日期次数加一；`merge` 对同一天的次数求和；`retract` 减一，只有降到零才删除该日期。次数相加使用溢出检查。

假设 `20261002` 出现两次，撤回其中一次后，这一天仍然存在。若只用集合并在撤回时直接删除，就会把仍然存在的日期误删，连续段可能被错误切断。取结果只看正计数日期是否存在，次数本身不增加连续长度。

`getValue` 排序键集合后扫描，不修改状态；`resetAccumulator` 清空计数。撤回非法日期与累加非法日期一样忽略；撤回一个从未存在的合法日期会抛状态异常。

## 普通 Map 与长期运行的边界

这里使用可推断的普通 Java Map，使算法和撤回关系可直接阅读。它不等价于为每个日期提供独立的状态后端访问或自动清理。大规模长期状态可研究 `MapView`，但更换容器仍不能省略窗口、保留范围和恢复兼容性设计。本例验证有界 SQL 执行及直接的撤回、合并语义，没有宣称覆盖所有流式窗口、checkpoint 或故障恢复场景。
