# Flink多列展开：固定行结构与对齐补齐

对应代码：[FlinkTransArray.java](FlinkTransArray.java)。适用版本：Flink 2.3.0 / Java 17。本篇解释同目录这一份实现，保留与 Hive 案例一致的业务规则，并明确引擎接口上的变化。

## 为什么统一输出键与片段数组

Hive 原实现可以根据参数确定若干键列和展开列。本例迁移时固定为一列字符串键与一个字符串数组，输出结构是 `row_key STRING, parts ARRAY<STRING>`。固定结构使优化器在执行前确定类型，也避免写多个几乎相同的类。

输入 `key=u`、分隔符逗号、数据列 `['a,b','10']`，输出两行：第一行的 `parts` 为 `['a','10']`，第二行为 `['b',NULL]`。这是按位置对齐的 zip 展开，**不是多列之间做笛卡尔积**。

## 拆分一次，以最长列决定行数

分隔符先用 `Pattern.quote` 转成字面模式，每列只拆一次；`-1` 保留尾部空串。以最长拆分结果决定行数，短列和原本为空值的列按位置填 `NULL`。所有数据列都为空值时仍输出一行空片段，保留键对应的记录。

分隔符为空值或空串、数据列数组为空值或零长度时抛异常；数组内某个元素为空值则是合法的数据缺失。键可以为空值。只支持字符串列，多个键或其他类型的键应另行定义清晰的结构。

## 每行都创建快照

每个输出位置都分配新的片段数组和新的行对象。若在循环里复用同一个数组并修改它，先前发送出去的行可能看到后续的值；创建独立对象使一行输出对应一个稳定快照。

设输入列数为 `c`、最大分段数为 `r`，对齐输出需要处理约 `c × r` 个位置，还需保存各列拆分后的结果。输出行数显著增加时，下游算子和网络成本也会一起增加。

## Flink 表函数如何发送多行

继承 `TableFunction<Row>`，`eval(key,separator,String[] columns)` 返回 `void`，通过多次 `collect(Row.of(key,aligned))` 发出结果。`Row` 本身不能从泛型中说明字段名与字段类型，因此在方法上使用 `FunctionHint` 和 `DataTypeHint` 声明 `ROW<row_key STRING, parts ARRAY<STRING>>`。

SQL 关联形状是 `LATERAL TABLE(trans_note(k, ',', ARRAY['a,b','10'])) AS x(row_key,parts)`。这里的数据列集中在一个数组参数里，并非任意个参数自动变成输出列。需要恢复为多列时，在下游显式投影数组位置；Flink SQL 数组位置从 1 开始。

表函数按调用发送各行，不额外构造一个包含全部输出行的列表；但当前实现仍先拆完全部输入列，不能据此声称完全没有内存缓冲。
