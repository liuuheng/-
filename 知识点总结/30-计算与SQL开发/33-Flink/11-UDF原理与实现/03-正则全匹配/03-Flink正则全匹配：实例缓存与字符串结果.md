# Flink正则全匹配：实例缓存与字符串结果

对应代码：[FlinkRegexpAll.java](FlinkRegexpAll.java)。适用版本：Flink 2.3.0 / Java 17。本篇解释同目录这一份实现，保留与 Hive 案例一致的业务规则，并明确引擎接口上的变化。

## 业务规则与返回契约

按顺序收集所有不重叠的**完整匹配**，每个匹配后追加分隔符。`a12b34` 配合 `[0-9]+` 与逗号，结果是 `12,34,`。输出为 `STRING`，不是字符串数组，也不是某个捕获组。

任一显式参数为空值时返回 `NULL`；最终未积累出字符也返回 `NULL`。非法正则直接抛异常，由引擎包装为作业错误，避免混淆“模式写错”与“没有匹配”。

## 为什么只缓存 Pattern

`cachedRegex` 和 `cachedPattern` 只缓存本实例最近的一条模式。模式改变时重新编译，编译成功之后才替换缓存键；缓存容量固定，不随不同规则数量增长。字段标为 `transient`，反序列化后可由下一行重新构造。

`Matcher` 含有当前文本和匹配位置，必须逐行创建。循环中用 `find()` 移动位置，用 `group()` 取完整匹配，使用当前行的 `StringBuilder` 拼接；不共享匹配游标。缓存字段服务于引擎管理的函数实例，不应把同一实例另行交给多个业务线程并发调用。

## 不能省略的边界

`DOTALL` 仅使点号可匹配换行，不等于忽略大小写或启用多行锚点。末尾分隔符是业务契约的一部分。零长度匹配配合空分隔符也可能生成空结果，因此返回 `NULL` 不必然表示一次都没匹配到。

单项缓存只减少重复编译，不能消除复杂正则的回溯耗时；规则交替变化时也仍会反复编译。若下游需要精确区分匹配项，应该另行设计数组返回值，而不能直接把当前字符串当数组解析。

## Flink 的接口和生命周期

继承 `ScalarFunction`，提供 `eval(source,regex)` 与 `eval(source,regex,delimiter)`；前者委托后者，默认分隔符为逗号。字段缓存随函数实例存在，调用时直接使用 Java 字符串，返回值由签名推断为可空字符串。

运行期派生缓存不属于聚合状态，也不需要 checkpoint 保存。实例重新创建时只损失一次模式编译的复用，不改变匹配结果。不要把该缓存当成跨并行任务共享的规则中心。
