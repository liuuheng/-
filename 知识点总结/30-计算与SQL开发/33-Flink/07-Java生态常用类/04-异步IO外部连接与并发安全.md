# 异步 I/O、外部连接与并发安全

> 目标：外部查询不阻塞 Flink 算子线程；并发量有上限；连接可复用；超时和重试有明确边界；失败不会悄悄丢数据；资源数量可以按并行度核算。

## 1. 为什么普通同步调用会拖垮吞吐

如果同步 HTTP/JDBC 查询平均耗时 50 ms，一个单线程算子理论上每秒最多完成约 20 次查询：

```text
吞吐 ≈ 1 / 0.05 s = 20 records/s
```

把并行度调到 100 虽然可能提高吞吐，却会同时增加 Task、网络连接、内存和调度开销。异步 I/O 允许一个 SubTask 同时挂起多个请求，等待期间继续接收输入；但“异步”不代表无限并发，仍必须通过 `capacity` 限制在途请求。

## 2. 三种常见实现及判断

| 实现 | 是否真正异步 | 适用情况 | 主要风险 |
| --- | --- | --- | --- |
| 在 `map()` 中同步调用 JDBC/HTTP | 否 | 低吞吐、低延迟要求不高 | 阻塞算子线程，反压明显 |
| 把同步调用扔进自建线程池 | 部分 | 客户端完全没有异步 API 时的折中 | 线程池、队列、取消和关闭复杂，容易把压力转移到内存 |
| `RichAsyncFunction` + 原生异步客户端 | 是 | HTTP、异步数据库/缓存客户端 | 需要正确处理回调、超时、重试和容量 |

优先使用客户端原生的异步 API。下面示例使用 Java 11 起提供的 `java.net.http.HttpClient#sendAsync`，Java 17 可直接使用。

## 3. 配置与输出模型

```java
package com.example.flink.lookup;

import java.io.Serializable;
import java.net.URI;
import java.time.Duration;
import java.util.Objects;

public final class LookupConfig implements Serializable {
    private static final long serialVersionUID = 1L;

    private final URI baseUri;
    private final String bearerTokenEnvName;
    private final Duration connectTimeout;
    private final Duration requestTimeout;

    public LookupConfig(
            URI baseUri,
            String bearerTokenEnvName,
            Duration connectTimeout,
            Duration requestTimeout) {
        this.baseUri = Objects.requireNonNull(baseUri);
        this.bearerTokenEnvName = requireText(
                bearerTokenEnvName, "bearerTokenEnvName");
        this.connectTimeout = requirePositive(connectTimeout, "connectTimeout");
        this.requestTimeout = requirePositive(requestTimeout, "requestTimeout");
    }

    private static String requireText(String value, String name) {
        if (value == null || value.trim().isEmpty()) {
            throw new IllegalArgumentException(name + " must not be blank");
        }
        return value.trim();
    }

    private static Duration requirePositive(Duration value, String name) {
        Objects.requireNonNull(value, name);
        if (value.isZero() || value.isNegative()) {
            throw new IllegalArgumentException(name + " must be positive");
        }
        return value;
    }

    public URI getBaseUri() { return baseUri; }
    public String getBearerTokenEnvName() { return bearerTokenEnvName; }
    public Duration getConnectTimeout() { return connectTimeout; }
    public Duration getRequestTimeout() { return requestTimeout; }

    @Override
    public String toString() {
        return "LookupConfig{baseUri=" + baseUri
                + ", bearerToken=SecretRef, connectTimeout=" + connectTimeout
                + ", requestTimeout=" + requestTimeout + '}';
    }
}
```

`LookupConfig` 只保存 Secret 环境变量名，避免 bearer token 随函数闭包进入序列化 JobGraph。该环境变量必须在每个 TaskManager 可见；若平台支持 Vault/KMS/Secret Manager，应保存 Secret URI 并在 `open()` 使用工作负载身份解析。不要把 token 作为 CLI 参数。

输出事件要能区分“查到”“不存在”，不要用空集合把输入静默吞掉：

```java
public class EnrichedOrder {
    private OrderEvent order;
    private String customerLevel;
    private String lookupStatus;

    public EnrichedOrder() {}

    public EnrichedOrder(OrderEvent order, String customerLevel, String lookupStatus) {
        this.order = order;
        this.customerLevel = customerLevel;
        this.lookupStatus = lookupStatus;
    }

    public static EnrichedOrder found(OrderEvent order, String level) {
        return new EnrichedOrder(order, level, "FOUND");
    }

    public static EnrichedOrder notFound(OrderEvent order) {
        return new EnrichedOrder(order, null, "NOT_FOUND");
    }

    public OrderEvent getOrder() { return order; }
    public void setOrder(OrderEvent order) { this.order = order; }
    public String getCustomerLevel() { return customerLevel; }
    public void setCustomerLevel(String customerLevel) {
        this.customerLevel = customerLevel;
    }
    public String getLookupStatus() { return lookupStatus; }
    public void setLookupStatus(String lookupStatus) {
        this.lookupStatus = lookupStatus;
    }
}
```

## 4. 原生异步 HTTP 查询函数

```java
package com.example.flink.lookup;

import com.example.flink.model.OrderEvent;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.apache.flink.configuration.Configuration;
import org.apache.flink.metrics.Gauge;
import org.apache.flink.streaming.api.functions.async.ResultFuture;
import org.apache.flink.streaming.api.functions.async.RichAsyncFunction;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import java.net.URI;
import java.net.URLEncoder;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.time.Duration;
import java.util.Collections;
import java.util.concurrent.CompletionException;
import java.util.concurrent.TimeoutException;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.atomic.AtomicLong;

public final class CustomerAsyncLookupFunction
        extends RichAsyncFunction<OrderEvent, EnrichedOrder> {

    private static final Logger LOG =
            LoggerFactory.getLogger(CustomerAsyncLookupFunction.class);

    private final LookupConfig config;

    private transient HttpClient httpClient;
    private transient ObjectMapper objectMapper;
    private transient String bearerToken;
    private transient AtomicInteger inFlight;
    private transient AtomicLong succeeded;
    private transient AtomicLong failed;

    public CustomerAsyncLookupFunction(LookupConfig config) {
        this.config = config;
    }

    @Override
    public void open(Configuration parameters) {
        this.bearerToken = System.getenv(config.getBearerTokenEnvName());
        if (bearerToken == null || bearerToken.trim().isEmpty()) {
            throw new IllegalStateException("required lookup Secret is unavailable");
        }
        this.httpClient = HttpClient.newBuilder()
                .connectTimeout(config.getConnectTimeout())
                .followRedirects(HttpClient.Redirect.NEVER)
                .version(HttpClient.Version.HTTP_1_1)
                .build();
        this.objectMapper = new ObjectMapper();
        this.inFlight = new AtomicInteger();
        this.succeeded = new AtomicLong();
        this.failed = new AtomicLong();

        getRuntimeContext().getMetricGroup()
                .gauge("customer_lookup_in_flight", (Gauge<Integer>) inFlight::get);
        getRuntimeContext().getMetricGroup()
                .gauge("customer_lookup_succeeded", (Gauge<Long>) succeeded::get);
        getRuntimeContext().getMetricGroup()
                .gauge("customer_lookup_failed", (Gauge<Long>) failed::get);
    }

    @Override
    public void asyncInvoke(
            OrderEvent input,
            ResultFuture<EnrichedOrder> resultFuture) {
        inFlight.incrementAndGet();
        HttpRequest request;
        try {
            request = buildRequest(input);
        } catch (Exception e) {
            inFlight.decrementAndGet();
            failed.incrementAndGet();
            resultFuture.completeExceptionally(e);
            return;
        }

        httpClient.sendAsync(request, HttpResponse.BodyHandlers.ofString())
                .whenComplete((response, throwable) -> {
                    try {
                        if (throwable != null) {
                            failed.incrementAndGet();
                            resultFuture.completeExceptionally(
                                    classifyTransportFailure(throwable));
                            return;
                        }
                        completeFromResponse(input, response, resultFuture);
                    } catch (Throwable callbackFailure) {
                        failed.incrementAndGet();
                        resultFuture.completeExceptionally(callbackFailure);
                    } finally {
                        inFlight.decrementAndGet();
                    }
                });
    }

    private HttpRequest buildRequest(OrderEvent input) {
        String customerId = input.getOrderId(); // 示例：真实模型应使用 customerId。
        if (customerId == null || customerId.trim().isEmpty()) {
            throw new NonRetryableLookupException("customerId is blank");
        }
        String encoded = URLEncoder.encode(customerId, StandardCharsets.UTF_8);
        URI uri = config.getBaseUri().resolve("/v1/customers?id=" + encoded);

        return HttpRequest.newBuilder(uri)
                .timeout(config.getRequestTimeout())
                .header("Accept", "application/json")
                .header("Authorization", "Bearer " + bearerToken)
                .GET()
                .build();
    }

    private void completeFromResponse(
            OrderEvent input,
            HttpResponse<String> response,
            ResultFuture<EnrichedOrder> resultFuture) throws Exception {
        int status = response.statusCode();
        if (status == 200) {
            JsonNode root = objectMapper.readTree(response.body());
            JsonNode levelNode = root.get("customerLevel");
            if (levelNode == null || !levelNode.isTextual()
                    || levelNode.textValue().trim().isEmpty()) {
                throw new NonRetryableLookupException(
                        "lookup response has no customerLevel");
            }
            succeeded.incrementAndGet();
            resultFuture.complete(Collections.singletonList(
                    EnrichedOrder.found(input, levelNode.textValue().trim())));
            return;
        }

        if (status == 404) {
            succeeded.incrementAndGet();
            resultFuture.complete(Collections.singletonList(
                    EnrichedOrder.notFound(input)));
            return;
        }

        if (status == 408 || status == 429 || status >= 500) {
            throw new RetryableLookupException("retryable HTTP status=" + status);
        }

        // 不记录响应 body；它可能包含服务端内部信息或敏感数据。
        throw new NonRetryableLookupException(
                "non-retryable HTTP status=" + status);
    }

    private static RuntimeException classifyTransportFailure(Throwable error) {
        Throwable current = error;
        while (current instanceof CompletionException && current.getCause() != null) {
            current = current.getCause();
        }
        return new RetryableLookupException(
                "lookup transport failed: " + current.getClass().getSimpleName(), current);
    }

    @Override
    public void timeout(
            OrderEvent input,
            ResultFuture<EnrichedOrder> resultFuture) {
        failed.incrementAndGet();
        // 严格语义：不静默丢弃，也不伪造默认值，让作业失败并由恢复策略处理。
        resultFuture.completeExceptionally(new TimeoutException(
                "customer lookup exceeded async operator timeout"));
    }

    public static final class RetryableLookupException extends RuntimeException {
        public RetryableLookupException(String message) { super(message); }
        public RetryableLookupException(String message, Throwable cause) {
            super(message, cause);
        }
    }

    public static final class NonRetryableLookupException extends RuntimeException {
        public NonRetryableLookupException(String message) { super(message); }
    }
}
```

### 为什么没有在 `close()` 关闭 JDK `HttpClient`

Java 17 的 `HttpClient` 没有实现 `AutoCloseable`。实例应复用，而不是逐条创建。如果改用自建 `ExecutorService`，则必须保存执行器引用并在 `close()` 中执行“停止接收 → 有界等待 → `shutdownNow`”流程；若使用 OkHttp/Apache HttpClient，则按照相应客户端的连接池和关闭契约处理。

## 5. 接入 Flink Async I/O 与重试

Flink 1.17 已支持 Async I/O retry。只重试明确的瞬态异常：连接失败、429、部分 5xx；不要重试参数错误、鉴权失败、协议错误等永久性失败。

```java
import org.apache.flink.streaming.api.datastream.AsyncDataStream;
import org.apache.flink.streaming.api.datastream.SingleOutputStreamOperator;
import org.apache.flink.streaming.api.functions.async.AsyncRetryStrategy;
import org.apache.flink.streaming.util.retryable.AsyncRetryStrategies;

import java.util.concurrent.TimeUnit;

int maxAttempts = 3;
long retryDelayMs = 200L;
long totalTimeoutMs = 3_000L;
int capacityPerSubtask = 100;

AsyncRetryStrategy<EnrichedOrder> retryStrategy =
        new AsyncRetryStrategies.FixedDelayRetryStrategyBuilder<EnrichedOrder>(
                maxAttempts, retryDelayMs)
                .ifException(error ->
                        error instanceof CustomerAsyncLookupFunction.RetryableLookupException)
                .build();

SingleOutputStreamOperator<EnrichedOrder> enriched =
        AsyncDataStream.unorderedWaitWithRetry(
                orders,
                new CustomerAsyncLookupFunction(lookupConfig),
                totalTimeoutMs,
                TimeUnit.MILLISECONDS,
                capacityPerSubtask,
                retryStrategy)
        .name("async-customer-lookup")
        .uid("async-customer-lookup-v1");
```

参数语义：

- `maxAttempts` 包含首次请求在内还是仅额外重试次数，应以当前 Flink API/测试确认，不要仅凭变量名猜测；上线前通过故障桩验证实际调用次数。
- operator timeout 覆盖从首次调用到最终完成的总时间，包含重试等待。
- `capacity` 是每个 AsyncWaitOperator SubTask 的最大并发。总并发近似为 `capacity × operator parallelism`。
- `unorderedWait` 延迟和开销较低，但输出顺序可改变；event time 下 watermark 仍会形成顺序边界。
- `orderedWait` 保持输入顺序，但慢请求会阻塞后续已完成结果，产生 head-of-line blocking。

### 容量估算

假设外部服务允许此作业最多 800 个并发请求，异步算子并行度为 8，预留 20% 给重启重叠和波动：

```text
capacityPerSubtask <= floor(800 × 0.8 / 8) = 80
```

不能把 capacity 直接设置成 800；那会形成最多 6400 个在途请求。

## 6. 超时是分层的

至少存在三层：

1. connect timeout：建立新连接的上限；连接复用时不生效。
2. request timeout：单次 HTTP 请求的上限。
3. Async operator timeout：首次尝试、重试和退避的总上限。

应满足类似：

```text
connect timeout < request timeout < async operator total timeout
```

例如单次请求 800 ms、最多 3 次尝试、两次 200 ms 退避，operator timeout 至少要覆盖：

```text
3 × 800 ms + 2 × 200 ms + 调度余量
```

如果三个超时都设成 1 秒，那么重试策略几乎没有实际执行空间。

## 7. 重试风暴与幂等

一次外部故障可能触发三层重试：

- HTTP Client/SDK 内部重试；
- Async I/O 重试；
- Flink Task/Job 重启后重放数据。

若每层都重试 3 次，最坏情况不是 3 次，而可能接近乘法放大。生产中必须选定主要重试层，设置总时间预算，并加入 jitter 或由上游统一退避。

查询通常天然幂等；写请求则必须使用业务幂等键，例如 `eventId`，并由服务端唯一约束或事务保证。仅在客户端“认为只发送一次”不能形成 exactly-once。

## 8. JDBC 的正确边界

JDBC 本身是阻塞 API。常见策略：

- 低吞吐维表查询：`RichFunction.open()` 创建小连接池，同步查询，但严格限制并行度和超时；
- 高吞吐维表查询：使用异步数据库驱动、缓存、Flink Lookup Join cache，或把维表广播到 State；
- 批量写入：优先使用 Flink 官方 JDBC Sink，明确批次、flush interval、重试和幂等；
- 不要为了“异步”创建无界线程池包住 JDBC。

连接池总量计算：

```text
总最大连接 ≈ poolMaximumSize × sink/lookup并行度 × 同类作业实例数
```

数据库的最大连接数还要给管理、迁移、其他应用和故障重连留余量。

## 9. 并发安全检查

- `ObjectMapper` 完成配置后可并发复用；不要在请求处理中修改配置。
- `DateTimeFormatter` 不可变、线程安全；`SimpleDateFormat` 不是。
- 异步回调运行在线程池线程，不要假设 MDC、ThreadLocal 或 Flink mailbox 上下文自动传播。
- 不要从异步回调直接访问普通非线程安全集合。
- `ResultFuture` 对每次输入必须最终完成或异常完成；不要遗漏分支。
- operator timeout 后底层 HTTP future 可能稍后才回调；Flink 会处理已经超时的 `ResultFuture`，但示例中的运维计数可能重复，因此准确业务成功/失败数应在下游确定性结果流中统计，客户端回调指标只用于运行状态观察。
- 不要在 `asyncInvoke()` 内调用 `.get()`/`.join()`，否则重新变成阻塞。
- 取消或 timeout 后，底层请求是否仍继续占用资源取决于客户端；需要用故障测试观察。

## 10. 上线验证

至少模拟：

- DNS/连接失败；
- 200、404、400、401、429、500；
- 返回非法 JSON 和超大响应；
- 单请求超时与总超时；
- 50% 慢请求下的吞吐、反压和 watermark；
- checkpoint 期间存在在途请求；
- TaskManager kill 后请求重放；
- 外部系统恢复时是否出现重试洪峰；
- 并行度变化后的总连接数和总并发数。
