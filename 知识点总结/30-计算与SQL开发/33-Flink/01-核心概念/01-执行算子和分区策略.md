# 执行算子和分区策略

## 1. 两类概念

学习 Flink 执行图时，可以先把 API 分成两类：

```text
执行算子
分区策略
```

执行算子是真正运行任务的节点。

分区策略决定数据从上游算子发送到下游算子的方式。

简单来说：

```text
执行算子是图上的点
分区策略是图上的边
```

## 2. 执行算子

执行算子会真正执行计算或 IO，会运行 Task，也会占用 slot。

常见执行算子：

| 执行算子 | 说明 |
|---|---|
| `source` | 数据源，例如 socket、Kafka、文件 |
| `map()` | 一进一出转换 |
| `flatMap()` | 一进多出或一进零出转换 |
| `filter()` | 过滤数据 |
| `sum()` | 聚合计算 |
| `print()` | 输出到控制台 |

执行算子通常可以设置：

```java
.name("算子名称")
.setParallelism(2)
.slotSharingGroup("g1")
```

原因是它们会出现在 Flink Web UI 的执行图节点中。

## 3. 分区策略

分区策略只负责决定数据如何从上游发送到下游，不会单独运行 Task，也不会单独占用 slot。

常见分区策略：

| 分区策略 | 说明 |
|---|---|
| `keyBy()` | 按 key 分区，相同 key 进入同一个下游并行子任务 |
| `rebalance()` | 全局轮询分发 |
| `rescale()` | 局部轮询分发 |
| `shuffle()` | 随机分发 |
| `broadcast()` | 广播到所有下游并行子任务 |
| `global()` | 全部发送到下游第一个并行子任务 |
| `forward()` | 上下游并行度一致时一对一直连 |

例如：

```java
.flatMap(...)
.keyBy(WordCount::getWord)
.sum("count")
```

这里 `keyBy()` 不是一个独立执行算子，而是控制：

```text
flatMap 的输出数据如何发送给 sum 的不同并行子任务
```

## 4. 为什么 keyBy 不单独占 slot

slot 是给真正运行的 Task 使用的。

例如下面这段代码：

```java
env.socketTextStream("localhost", 8888)
        .flatMap(...)
        .keyBy(WordCount::getWord)
        .sum("count")
        .print();
```

真正占用 slot 的是：

```text
source
flatMap
sum
print
```

`keyBy()` 是 `flatMap -> sum` 之间的分区规则，不是独立 Task。

所以不能这样计算：

```text
keyBy = 2 个 slot
```

而应该看上下游执行算子的并行度和 slot 共享组。

## 5. 为什么 name 只能给执行算子

`.name()` 的作用是给执行图中的节点起名字。

执行算子会成为执行图中的节点，所以可以命名：

```java
.map(...).name("M1")
.flatMap(...).name("切分单词")
.sum("count").name("按单词求和")
.print().name("控制台输出")
```

分区策略通常只是执行图中两节点之间的边，不是独立节点，所以不能单独命名：

```java
.keyBy(...).name("按 key 分区")     // 不可以
.rebalance().name("重新均衡")       // 不可以
```

如果想表达 `keyBy` 后面的计算含义，可以给后面的执行算子命名：

```java
.keyBy(WordCount::getWord)
.sum("count")
.name("按 word 分组求和")
```

## 6. slot 计算示例

例如代码：

```java
env.setParallelism(2);

env.socketTextStream("localhost", 8888)
        .flatMap(...).slotSharingGroup("g1")
        .keyBy(WordCount::getWord)
        .sum("count").slotSharingGroup("g2")
        .print().slotSharingGroup("g3");
```

可以这样计算 slot：

```text
default: source = 1
g1: flatMap = 2
g2: sum = 2
g3: print = 2
```

总共需要：

```text
1 + 2 + 2 + 2 = 7 个 slot
```

这里没有把 `keyBy()` 单独算进去，因为它是分区策略，不是执行算子。

## 7. 小结

一句话记忆：

```text
执行算子是点，占 slot，可以 name
分区策略是边，不占 slot，不能 name
```

判断 slot 数量时，重点看：

```text
执行算子的并行度
slotSharingGroup 的分组情况
source 是否单独属于 default 组
```
