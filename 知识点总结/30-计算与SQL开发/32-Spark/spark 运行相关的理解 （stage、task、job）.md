# Spark：Stage / Task 相关说明

## 1. 核心概念速览

### 1.1 DAG（有向无环图）
Spark 将作业编译为 **DAG**：由一系列 **Transformation** 与触发执行的 **Action**（如 `collect`、`save`、`count`）组成。

### 1.2 宽窄依赖（决定是否容易出现 Shuffle / Stage 切分）
- **窄依赖（narrow）**：父分区最多被子分区一对一消费（典型：`map`、`filter`）。通常 **不需要 shuffle**。
- **宽依赖（wide）**：子分区依赖多个父分区（典型：`groupBy`、`repartition`、某些 `join`）。通常会引入 **shuffle**，并常作为 **Stage 边界**的主要来源。

### 1.3 Stage 是什么
**Stage** 可以理解为：DAG 中被执行边界（最常见是 **shuffle 边界**）切开的一段 **固定物理流水线**。  
从上一个边界之后，到下一个边界之前，这一段计划的“算子组合”是相对固定的。

### 1.4 Task 是什么
**Task** 是 **同一个 Stage** 的这段流水线，在 **不同输入分区（partition）** 上的并行实例。

---

## 2. 结论：同一 Stage 里的 Task 会不会“一个做 A、一个做 B”？

**结论**：同一个 Stage 内的所有 Task，执行的是 **同一套计算逻辑**（同一段物理计划的同一条流水线），只是在 **不同分区数据** 上运行。  
不会出现“这个 Task 跑一套完全不同的算子链 / 完全不同的执行计划（互不相干的事件 A vs 事件 B）”。

更严谨的表述：
- **同一 Stage**：同一套 Task 执行路径（常见表现为同一套 WholeStageCodegen 融合代码或等价闭包），对不同 **partition index** 的数据执行。
- **差异来源**：输入分区不同、数据量不同、是否空分区、倾斜与否、资源与调度差异 → **耗时不同**，但 **不是逻辑分裂成两套 pipeline**。

---

## 3. 记忆模型（类比）
- **Stage = 同一套“菜谱”**（固定的物理流水线片段）
- **Task = 同一菜谱对不同“食材分片（partition）”各做一遍**
- **Shuffle ≈ 换生产线**：下一阶段通常会重新分区并执行下一阶段计划（因此会进入新的 Stage）

---

## 4. 补充：为什么“没有 shuffle 也可能有多个 Stage”？
教学上常说“Stage 由 shuffle 切开”，这最常见且好用；但更严谨地说：
- Stage 边界 **主要由 shuffle（宽依赖）驱动**
- 也可能受 **其它执行边界/优化与运行时改写**影响（不同版本与具体计划有关）

另外 **AQE（自适应执行）** 可能在运行时调整分区、读取方式等，但这是 **改写后的计划**重新组织 stage/task，而不是在同一 stage 内混两套无关逻辑。

---

## 5. 你可能看到“好像不一样”的常见原因（但仍属于同一 Stage 逻辑）

1. **Spark UI / WholeStageCodegen 展示差异**  
   UI 把多个算子包裹显示，容易误以为 task 不同；本质是展示聚合，不是逻辑分裂。

2. **数据驱动的分支表达式**  
   例如 `CASE WHEN`，不同数据走不同分支，但仍是 **同一段表达式求值代码**。

3. **空分区 / 数据量差异**  
   某些 task 很快结束，看起来像“没做事”，但仍是同一逻辑，只是输入极少或为空。

4. **推测执行（speculation）**  
   同一 partition 可能出现重复 attempt（并行尝试），看起来像“多干了活”，但仍是 **同逻辑重复**，最终采纳其中一个成功结果。

5. **误解来源：partial / merge 分布在不同 Stage**  
   例如聚合的 **partial** 与 **final merge** 常在 shuffle 前后分属 **不同 Stage**——这是 **跨 Stage** 的差异，不是 **同一 Stage 内** task 执行不同套算子链。

---

## 6. 一句话总结
**Wide dependency →（通常）shuffle → 新 Stage；同一 Stage 内所有 Task 并行执行同一计划的不同分区实例。**
