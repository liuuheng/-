# 单点登录语境与开发人员常用术语地图

> 目标：以“单点登录（SSO）”为起点，横向认识 SaaS 公司和软件开发工作中经常出现的概念。
>
> 阅读原则：先知道一个词解决什么问题、通常在哪里出现；需要真正使用时，再深入协议细节和实现原理。

## 1. 身份、登录与权限

| 术语 | 英文/缩写 | 一句话理解 |
|---|---|---|
| 单点登录 | Single Sign-On，SSO | 登录一次后，可以进入多个互相信任的系统。 |
| 单点登出 | Single Logout，SLO | 从一个入口退出后，同时结束多个系统中的会话。 |
| 身份认证 | Authentication，AuthN | 确认访问者是谁。 |
| 授权 | Authorization，AuthZ | 确认用户可以做什么。 |
| 身份提供商 | Identity Provider，IdP | 负责验证用户身份并提供认证结果的系统。 |
| 服务提供商 | Service Provider，SP | 使用身份认证结果向用户提供业务功能的系统。 |
| 身份联邦 | Identity Federation | 让不同组织或身份域互相信任身份结果。 |
| 多因素认证 | Multi-Factor Authentication，MFA | 使用密码、设备、验证码等多个因素确认身份。 |
| 双因素认证 | Two-Factor Authentication，2FA | 使用两类认证因素，是 MFA 的一种。 |
| 无密码认证 | Passwordless | 使用验证码、安全密钥或生物识别代替密码。 |
| 第三方登录 | Social Login | 使用微信、Google、GitHub 等已有身份登录其他应用。 |
| 统一身份管理 | Identity and Access Management，IAM | 集中管理用户身份、认证和访问权限。 |
| 特权访问管理 | Privileged Access Management，PAM | 管理管理员、运维等高权限账号的访问。 |
| 基于角色的权限控制 | Role-Based Access Control，RBAC | 根据角色给用户分配权限。 |
| 基于属性的权限控制 | Attribute-Based Access Control，ABAC | 根据用户、资源、环境等属性动态判断权限。 |
| 访问控制列表 | Access Control List，ACL | 在资源上明确记录哪些主体拥有哪些权限。 |
| 最小权限原则 | Principle of Least Privilege | 只提供完成工作所必需的最少权限。 |
| 零信任 | Zero Trust | 不因用户位于内网就默认可信，每次访问都需要验证。 |
| 条件访问 | Conditional Access | 根据设备、位置、时间和风险决定是否允许访问。 |
| 服务账号 | Service Account | 供程序或服务使用、而不是供自然人登录的账号。 |

### 常见协议、标准和凭证

| 术语 | 一句话理解 |
|---|---|
| OAuth 2.0 | 委托授权框架，让应用在限定范围内访问资源。 |
| OpenID Connect（OIDC） | 建立在 OAuth 2.0 之上的身份认证协议。 |
| SAML 2.0 | 企业 SSO 中常见的 XML 身份认证标准。 |
| CAS | 学校和传统企业系统中常见的集中认证协议。 |
| LDAP | 查询和维护用户、部门等目录信息的协议。 |
| Active Directory（AD） | 微软提供的企业目录和身份管理服务。 |
| Kerberos | 使用票据完成认证，常见于企业内网。 |
| SCIM | 在身份平台和 SaaS 应用之间同步用户、用户组与停用状态。 |
| JWT | 一种可签名的令牌格式，不等于完整的登录协议。 |
| Access Token | 调用受保护接口时使用的访问凭证。 |
| Refresh Token | Access Token 过期后，用来申请新令牌的凭证。 |
| ID Token | OIDC 中描述登录用户身份的令牌。 |
| Bearer Token | 谁持有谁就能使用的令牌，泄露后风险较大。 |
| Claims | 令牌中携带的用户、租户、角色等声明。 |
| Scope | 应用申请访问的能力或数据范围。 |
| Authorization Code | 登录授权完成后返回的一次性授权码。 |
| PKCE | 防止授权码被截获后冒用的安全机制。 |
| Client ID | 应用在认证平台中的公开标识。 |
| Client Secret | 服务端应用证明自身身份的机密凭证。 |
| Redirect URI | 认证完成后允许返回的应用地址。 |
| Callback | 外部流程完成后回到本系统的接口或页面。 |
| JWKS | 用于验证 JWT 签名的一组公开密钥。 |
| Issuer | 令牌的签发方。 |
| Audience | 令牌预期提供给哪个应用或服务。 |
| State | 关联认证请求与回调，也用于防范部分攻击。 |
| Nonce | 防止身份响应被重复利用的随机值。 |

### 账号生命周期

| 术语 | 一句话理解 |
|---|---|
| Provisioning | 为用户创建账号、分配资源与权限。 |
| Deprovisioning | 用户离职或失去资格后，停用账号并回收权限。 |
| JIT Provisioning | 用户首次 SSO 登录时即时创建本地账号。 |
| 账号映射 | 建立外部身份与本地账号的对应关系。 |
| 属性映射 | 对应姓名、邮箱、部门、员工编号等字段。 |
| 角色映射 | 将外部用户组转换为本系统角色。 |
| 身份源 | 用户和组织数据的权威来源。 |
| 孤儿账号 | 已经没有对应人员、但仍然存在的账号。 |
| 僵尸账号 | 长期不用但权限仍然有效的账号。 |

## 2. 浏览器、HTTP 与网络

| 术语 | 一句话理解 |
|---|---|
| HTTP | 浏览器、客户端与服务器交换请求和响应的应用层协议。 |
| HTTPS | 使用 TLS 加密的 HTTP。 |
| URL | 网络资源的完整地址。 |
| URI | 标识资源的通用形式，URL 是其中一种。 |
| 域名 | 便于人类记忆的网络地址名称。 |
| DNS | 将域名解析为 IP 地址。 |
| IP 地址 | 标识网络中设备或服务的地址。 |
| 端口 | 区分一台主机上不同网络服务的编号。 |
| TCP | 可靠、有序的传输协议。 |
| UDP | 更轻量但不保证可靠送达的传输协议。 |
| TLS | 为网络通信提供加密和身份验证。 |
| Cookie | 浏览器随请求发送的小段数据，常用于维持登录状态。 |
| Session | 服务端维护的一段用户会话状态。 |
| LocalStorage | 浏览器中的持久键值存储，可被 JavaScript 读取。 |
| SessionStorage | 生命周期通常限于当前标签页的浏览器存储。 |
| Same-Origin Policy | 浏览器限制不同源页面互相访问数据的安全规则。 |
| CORS | 服务器声明哪些跨源请求可以被浏览器允许。 |
| CSP | 限制页面可加载和执行哪些内容，降低 XSS 风险。 |
| HttpOnly | 禁止 JavaScript 直接读取 Cookie。 |
| Secure Cookie | 只允许 Cookie 通过 HTTPS 发送。 |
| SameSite | 控制 Cookie 在跨站场景下是否发送。 |
| HTTP 200 | 请求处理成功。 |
| HTTP 201 | 资源创建成功。 |
| HTTP 204 | 请求成功，但没有响应正文。 |
| HTTP 301/302 | 永久或临时重定向。 |
| HTTP 400 | 请求格式或参数有问题。 |
| HTTP 401 | 尚未通过身份认证。 |
| HTTP 403 | 已识别身份，但没有访问权限。 |
| HTTP 404 | 未找到目标资源。 |
| HTTP 409 | 请求与当前资源状态冲突。 |
| HTTP 429 | 请求过于频繁，被限流。 |
| HTTP 500 | 服务端发生未预期错误。 |
| HTTP 502 | 网关从上游服务收到了无效响应。 |
| HTTP 503 | 服务暂时不可用。 |
| HTTP 504 | 网关等待上游服务超时。 |
| 正向代理 | 代表客户端访问外部服务。 |
| 反向代理 | 代表服务端接收请求并转发到内部服务。 |
| 负载均衡 | 将请求分配到多个服务实例。 |
| CDN | 将静态内容缓存到靠近用户的节点。 |
| WebSocket | 浏览器与服务器之间保持双向长连接。 |
| SSE | 服务器通过一个长期 HTTP 连接持续向客户端推送事件。 |

## 3. API 与系统集成

| 术语 | 一句话理解 |
|---|---|
| API | 一个软件向另一个软件开放能力的接口。 |
| REST | 以资源和 HTTP 动作为核心的接口设计风格。 |
| RPC | 像调用本地函数一样调用远程服务。 |
| gRPC | 基于 HTTP/2 和 Protocol Buffers 的高性能 RPC 框架。 |
| GraphQL | 客户端按需声明所需字段的接口查询语言。 |
| Webhook | 事件发生时，一个系统主动通知另一个系统。 |
| SDK | 为某种语言封装好的开发工具和接口客户端。 |
| OpenAPI | 描述 HTTP API 结构的标准规范。 |
| Swagger | 常用于编辑、展示和调试 OpenAPI 文档的工具体系。 |
| Endpoint | API 的具体访问地址。 |
| Request | 客户端发给服务端的请求。 |
| Response | 服务端返回给客户端的结果。 |
| Header | 请求或响应中的元信息。 |
| Body | 请求或响应承载的主体数据。 |
| Query Parameter | 放在 URL 查询部分的参数。 |
| Path Parameter | URL 路径中的变量。 |
| Payload | 一次请求、消息或令牌实际携带的数据。 |
| 序列化 | 把对象转换成 JSON、二进制等可传输形式。 |
| 反序列化 | 把传输格式恢复为程序对象。 |
| 幂等性 | 同一操作重复执行不会产生额外副作用。 |
| 分页 | 将大量结果拆成多页返回。 |
| 限流 | 控制单位时间内允许的请求数量。 |
| 超时 | 等待操作超过设定时间后主动终止。 |
| 重试 | 请求失败后再次尝试。 |
| 指数退避 | 每次重试前逐渐增加等待时间。 |
| 熔断 | 下游持续失败时临时停止调用，避免故障扩大。 |
| 降级 | 故障或高负载时关闭次要能力，保住核心功能。 |
| API Gateway | 统一处理路由、认证、限流等 API 请求的入口。 |

## 5. 后端与服务端开发

| 术语 | 一句话理解 |
|---|---|
| Controller | 接收请求并组织响应的入口层。 |
| Service | 承载业务逻辑的服务层。 |
| Repository/DAO | 封装数据库访问逻辑。 |
| DTO | 在接口或系统层之间传递数据的对象。 |
| Entity | 与领域对象或数据库记录相关的数据对象。 |
| Middleware | 在请求进入核心业务前后统一处理认证、日志等逻辑。 |
| Dependency Injection | 由容器提供对象依赖，减少代码耦合。 |
| ORM | 用对象操作关系型数据库的映射工具。 |
| 事务 | 一组操作要么全部成功，要么全部失败。 |
| ACID | 数据库事务的原子性、一致性、隔离性和持久性。 |
| 并发 | 多个任务在相近时间内共同推进。 |
| 并行 | 多个任务在同一时刻实际同时执行。 |
| 线程 | 进程中的执行单元。 |
| 协程 | 由程序调度的轻量级并发单元。 |
| 同步 | 调用方等待操作完成后继续。 |
| 异步 | 调用发起后不必原地等待结果。 |
| 阻塞 | 执行单元在等待期间无法继续其他工作。 |
| 非阻塞 | 等待结果时仍可处理其他任务。 |
| 连接池 | 复用数据库或网络连接，降低创建成本。 |
| 线程池 | 复用工作线程并控制并发数量。 |
| 内存泄漏 | 不再需要的内存未被释放，导致占用持续增长。 |
| 垃圾回收 | 运行时自动释放不再使用的对象内存。 |

## 6. 数据库、缓存与搜索

| 术语 | 一句话理解 |
|---|---|
| 关系型数据库 | 使用表、行、列和关系组织数据。 |
| NoSQL | 非传统关系模型数据库的统称。 |
| SQL | 查询和操作关系型数据库的语言。 |
| Schema | 数据库对象、字段和约束的结构定义。 |
| 主键 | 唯一标识一条记录的字段或字段组合。 |
| 外键 | 表示不同表之间引用关系的约束。 |
| 索引 | 用额外的数据结构加快查询。 |
| 唯一索引 | 保证索引字段组合不重复。 |
| 全表扫描 | 查询需要检查表中的大量或全部记录。 |
| 执行计划 | 数据库准备怎样执行一条查询。 |
| 慢查询 | 执行耗时超过预期的查询。 |
| 锁 | 控制并发操作对数据的访问。 |
| 死锁 | 多个事务相互等待对方释放资源。 |
| 乐观锁 | 假设冲突较少，更新时检查版本是否变化。 |
| 悲观锁 | 操作前先锁定资源，阻止其他事务修改。 |
| 主从复制 | 将主库数据复制到一个或多个从库。 |
| 读写分离 | 写请求访问主库，读请求分散到从库。 |
| 分库分表 | 将大量数据分散到多个数据库或数据表。 |
| 数据迁移 | 将数据从旧结构或旧系统移动到新位置。 |
| 缓存 | 将热点数据保存在更快的介质中。 |
| 缓存穿透 | 持续查询不存在的数据，请求直接打到数据库。 |
| 缓存击穿 | 某个热点缓存失效，大量请求同时访问数据库。 |
| 缓存雪崩 | 大量缓存集中失效，引发数据库流量骤增。 |
| 缓存一致性 | 控制缓存数据与数据库数据保持合理一致。 |
| TTL | 数据在缓存或存储中的有效时间。 |
| 全文检索 | 按文本内容建立索引并进行搜索。 |
| 倒排索引 | 从词语反查包含该词语的文档。 |

## 7. 消息、事件与异步处理

| 术语 | 一句话理解 |
|---|---|
| 消息队列 | 在生产者和消费者之间暂存并传递消息。 |
| Producer | 发送消息的一方。 |
| Consumer | 接收并处理消息的一方。 |
| Topic | 对消息进行逻辑分类的主题。 |
| Partition | 将一个主题拆开，以提高吞吐量和并行能力。 |
| Consumer Group | 多个消费者共同分担同一组消息。 |
| 发布/订阅 | 发布者发送事件，多个订阅者分别接收。 |
| 事件驱动架构 | 系统通过事件的产生和消费进行协作。 |
| 消息积压 | 消费速度低于生产速度，未处理消息不断增加。 |
| 重复消费 | 同一条消息被处理多次。 |
| 消息丢失 | 消息未被可靠保存或处理。 |
| 顺序消息 | 需要按照特定先后顺序处理的消息。 |
| 延迟消息 | 到指定时间后才允许被消费的消息。 |
| 死信队列 | 存放多次处理失败或无法消费的消息。 |
| 最多一次 | 消息可能丢失，但不会重复处理。 |
| 至少一次 | 保证消息不丢，但可能重复处理。 |
| 恰好一次 | 业务效果看起来只发生一次，实现成本通常较高。 |
| 最终一致性 | 允许短暂不一致，但经过处理后达到一致状态。 |

| 容错 | 出现局部错误时避免整个系统失败。 |

## 9. 云计算、容器与基础设施

| 术语 | 一句话理解 |

## 18. 容易混淆的概念

### 认证与授权

- **认证**解决“你是谁”。
- **授权**解决“你能做什么”。
- 用户收到 `401`，通常是身份未确认；收到 `403`，通常是身份已确认但权限不足。

### OAuth 2.0、OIDC 与 SAML

- **OAuth 2.0**主要解决委托授权。
- **OIDC**在 OAuth 2.0 基础上增加身份认证。
- **SAML**主要用于企业身份联邦和浏览器 SSO。

### Cookie、Session 与 JWT

- **Cookie**是浏览器保存并发送数据的机制。
- **Session**通常是服务端保存的会话状态。
- **JWT**是一种令牌格式。
- 三者不是互斥选项：Cookie 中可以保存 Session ID，也可以保存 JWT。

### 401 与 403

- **401 Unauthorized**：实际通常表示“尚未认证”。
- **403 Forbidden**：已经识别用户，但拒绝访问。

### 同步、异步、阻塞与非阻塞

- 同步/异步描述结果如何返回或协作。
- 阻塞/非阻塞描述等待期间执行单元能否继续工作。
- 它们是两个维度，不应直接画等号。

### 并发与并行

- **并发**：多个任务在同一时间段内推进。
- **并行**：多个任务在同一时刻实际执行。

### 缓存与数据库

- 数据库通常保存权威、持久数据。
- 缓存主要提高访问速度，不应默认成为唯一数据来源。

### 消息队列与 Webhook

- 消息队列通常用于内部系统间可靠异步通信。
- Webhook 通常通过 HTTP 主动通知外部或独立系统。

### 单体与微服务

- 单体并不等于落后，微服务也不天然更先进。
- 微服务用部署独立性换来了网络、数据一致性和运维复杂度。

### 高可用与高性能

- **高可用**关注故障时能否继续服务。
- **高性能**关注处理速度和吞吐能力。
- 一个系统可以性能很好但不够可靠，也可以高可用但速度普通。

### SLA、SLO 与 SLI

- **SLI**是实际测量指标。
- **SLO**是内部或服务层面的目标。
- **SLA**通常是面向客户的正式承诺，可能包含违约责任。

### IaaS、PaaS 与 SaaS

- **IaaS**交付基础计算资源。
- **PaaS**交付开发和运行平台。
- **SaaS**交付可以直接使用的软件。

## 19. 从 SSO 出发的推荐学习路线

1. **先理解 Web 请求**：URL、DNS、HTTP、HTTPS、Cookie、状态码、重定向。
2. **再理解登录状态**：Session、Token、JWT、过期、刷新、登出。
3. **学习认证协议**：OAuth 2.0、OIDC、SAML，以及 IdP、SP、回调地址。
4. **补齐权限模型**：RBAC、ABAC、租户隔离、最小权限原则。
5. **学习接口协作**：REST、Webhook、幂等、重试、限流、熔断。
6. **理解数据与异步**：数据库、索引、事务、缓存、消息队列、最终一致性。
7. **理解部署和运行**：容器、Kubernetes、CI/CD、灰度、回滚。
8. **理解线上质量**：日志、指标、追踪、SLO、容量、容灾和安全。
9. **最后连接 SaaS 业务**：多租户、订阅、席位、客户成功、续费与开放平台。

## 20. SSO 开发排查速查表

| 现象 | 优先检查 |
|---|---|
| 登录后反复跳回登录页 | Cookie Domain、SameSite、Session 是否写入、回调处理是否成功。 |
| 回调地址错误 | Redirect URI 是否与身份平台登记值完全一致。 |
| Token 校验失败 | Issuer、Audience、签名算法、JWKS、有效期和服务器时间。 |
| 登录成功但找不到用户 | 外部用户 ID、邮箱、NameID 和账号映射规则。 |
| 登录成功但没有权限 | Claims、用户组、角色映射、默认角色和租户上下文。 |
| 开发环境正常、生产失败 | 域名、HTTPS、代理头、证书、回调白名单和环境配置。 |
| 偶发 401 | Token 刷新并发、会话过期、服务器时间偏差和缓存状态。 |
| 退出后还能访问 | 本地 Session、Cookie、Access Token 与 IdP 会话是否都被处理。 |
| 跨域请求没有 Cookie | CORS 凭证设置、SameSite、Secure、Domain 和前端请求配置。 |
| SAML 突然全部失败 | 签名证书是否过期或轮换，Metadata 是否更新。 |

## 21. 使用这份笔记的方法

- 第一次看到术语时，只需掌握“一句话理解”。
- 参加需求评审时，重点查看“开发人员常听到的表达”。
- 接入登录时，重点查看身份认证、HTTP、API、安全和排查部分。
- 遇到线上问题时，从状态码、日志、Trace ID、配置差异和依赖状态开始收集证据。
- 不要因为术语相近就认为它们等价；以协议文档、代码行为和实际数据为准。
