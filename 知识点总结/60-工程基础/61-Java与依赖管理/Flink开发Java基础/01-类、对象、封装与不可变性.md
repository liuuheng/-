# 01 类、对象、封装与不可变性

## 1. 为什么先复习对象

Flink 中流动的每一条数据，本质上都是一个 Java 对象。例如一条订单、一条用户行为日志、一个传感器事件，都可以表示为一个对象。

```java
Order order = new Order("o-1001", "u-01", 99.9);
```

后续的 `map`、`filter`、`keyBy` 和窗口聚合，处理的都是这样的对象。

## 2. 类和对象

类是模板，对象是按照模板创建出的实例。

```java
public class Order {
    private String orderId;
    private String userId;
    private double amount;

    public Order() {
    }

    public Order(String orderId, String userId, double amount) {
        this.orderId = orderId;
        this.userId = userId;
        this.amount = amount;
    }
}
```

其中：

- `Order` 是类。
- `orderId`、`userId`、`amount` 是字段，也称为成员变量。
- `new Order(...)` 会在堆内存中创建一个对象。
- 局部变量 `order` 保存的是对象引用，不是对象本身。

## 3. 引用类型和值类型

Java 基本类型直接保存值：

```java
int count = 10;
double amount = 99.9;
boolean paid = true;
```

引用类型保存对象的引用：

```java
Order first = new Order("o-1", "u-1", 10.0);
Order second = first;
```

此时 `first` 和 `second` 指向同一个对象：

```java
second.setAmount(20.0);
System.out.println(first.getAmount()); // 20.0
```

这件事在流处理中非常重要。如果复用并修改同一个对象，可能造成难以察觉的数据污染。

## 4. 封装

封装的核心是：字段通常设为 `private`，通过公开方法控制访问。

```java
public double getAmount() {
    return amount;
}

public void setAmount(double amount) {
    if (amount < 0) {
        throw new IllegalArgumentException("amount must not be negative");
    }
    this.amount = amount;
}
```

好处：

1. 外部代码不能随意破坏对象状态。
2. 修改规则时，可以集中调整 setter。
3. 符合 JavaBean 规范，便于 Flink 识别 POJO。

## 5. 构造方法

构造方法负责初始化对象。名称与类名相同，没有返回值。

```java
public Order() {
}

public Order(String orderId, String userId, double amount) {
    this.orderId = orderId;
    this.userId = userId;
    this.amount = amount;
}
```

对于 Flink POJO，公开的无参构造方法非常重要。Flink 在反序列化时需要先创建空对象，再填充字段。

## 6. `this` 关键字

`this` 代表当前对象。

```java
this.orderId = orderId;
```

左侧是当前对象字段，右侧是传入参数。二者重名时必须用 `this` 区分。

## 7. `equals()` 和 `hashCode()`

`==` 比较引用是否相同；`equals()` 通常用于比较业务意义上是否相等。

```java
String a = new String("u-1");
String b = new String("u-1");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
```

如果自定义对象需要作为 `HashMap` 的 key，必须正确重写 `equals()` 和 `hashCode()`。

```java
@Override
public boolean equals(Object o) {
    if (this == o) {
        return true;
    }
    if (!(o instanceof UserKey)) {
        return false;
    }
    UserKey that = (UserKey) o;
    return Objects.equals(userId, that.userId);
}

@Override
public int hashCode() {
    return Objects.hash(userId);
}
```

原则：如果两个对象 `equals()` 为 `true`，它们的 `hashCode()` 必须相同。

## 8. 可变对象和不可变对象

可变对象创建后还能修改：

```java
order.setAmount(100.0);
```

不可变对象创建后状态不再变化：

```java
public final class UserId {
    private final String value;

    public UserId(String value) {
        this.value = value;
    }

    public String getValue() {
        return value;
    }
}
```

不可变对象更容易理解，也更适合并发环境。但 Flink 1.17 的 POJO 识别规则通常需要无参构造方法和可写字段，因此事件对象常采用普通 JavaBean。业务代码中要避免不必要的对象复用。

## 9. Flink 场景示例

```java
DataStream<Order> orders = env.fromElements(
    new Order("o-1", "u-1", 20.0),
    new Order("o-2", "u-2", 80.0)
);

DataStream<Order> expensiveOrders =
    orders.filter(order -> order.getAmount() >= 50.0);
```

## 11. 阅读时常见问题

### 问题 1：不可变对象更安全，为什么 Flink 事件对象常使用带 setter 的 JavaBean？

这是两个目标之间的取舍。

普通 Java 设计中，不可变对象创建后不能再修改，更容易推理，也更适合并发读取：

```java
public final class Order {
    private final String userId;
    private final double amount;

    public Order(String userId, double amount) {
        this.userId = userId;
        this.amount = amount;
    }
}
```

但是，Flink 1.17 识别普通 POJO 时，通常希望对象具有公开无参构造方法和可写字段。反序列化过程可以粗略理解为：

```java
Order order = new Order();
order.setUserId("u-1");
order.setAmount(20.0);
```

因此，流中传输的事件对象常使用 JavaBean。它便于 Flink 识别和高效序列化。配置对象、值对象等不需要被 Flink 当作 POJO 处理的对象，仍然可以优先设计为不可变对象。

### 问题 2：既然 JavaBean 可以修改，怎样减少风险？

关键是不要随意共享和复用同一个可变对象。更稳妥的写法是每次输出新对象：

```java
return new Order(userId, amount);
```

不推荐为了少执行一次 `new`，反复修改并返回同一个对象：

```java
reusableOrder.setUserId(userId);
reusableOrder.setAmount(amount);
return reusableOrder;
```

如果下游仍持有上一次返回的引用，后续修改可能污染之前的数据。

### 问题 3：`final` 字段一定代表对象完全不可变吗？

不一定。`final` 只表示引用不能改指向：

```java
private final List<String> tags = new ArrayList<>();
```

虽然不能让 `tags` 指向另一个列表，但仍然可以执行：

```java
tags.add("vip");
```

真正的不可变对象还需要避免暴露可修改的内部集合，必要时返回只读视图或副本。

### 问题 4：事件对象是否必须重写 `equals()` 和 `hashCode()`？

不是所有事件对象都必须重写。只有当对象需要参与去重、集合成员判断，或者作为 `HashMap`、`HashSet` 的 key 时，才尤其重要。

如果只是通过：

```java
orders.keyBy(Order::getUserId);
```

使用字符串 `userId` 作为 key，那么重点是 `String` 的相等性，不是整个 `Order` 对象的相等性。
