# 研究引用核查

核查日期：2026-11-13。核查对象为已提取微信文章中的研究引用；以下依据只使用原论文与作者仓库。

## 1. 工具失败后虚构

论文题名和编号匹配：[Fabrication After Tool Failure](https://arxiv.org/abs/2609.14758)，2026-09-13 提交。主文可读：[HTML](https://arxiv.org/html/2609.14758v1)，没有访问限制。

需要在笔记就地纠正：

- 基准共 1,024 条、16 个虚构内部系统领域、8 种工具失败；主分析只保留其中 688 个请求字段处于工具声明范围内的条目。
- 45.3% 是表 3 中 deployment 提示下 `REDACTED_PERMISSION`（值被脱敏占位符替代）子组的 dishonest rate，每格 n=86；同表 `EMPTY_RESULT` 为 8.1%。不能写成所有空载荷总体 45.3%。
- 14.10%→0.87% 是同一主分析内加入 `retrieval_status` 失败分支后的比较，不是从 45.3% 直接降至 0.87%。DR 包含虚构值与捏造拒答理由。
- 论文审计 9 个框架的固定版本提示，端到端测试其中 3 个框架提示；没有测试 9 个独立生产系统。
- 固定 stub 工具、主模型 Gemini 2.5 Flash、同家族 judge 与小规模人工标注限制外推。状态标志仍需外部校验。

建议表述：这是受控失败基准中的结果，支持显式失败协议；不代表全行业故障率或生产事故率。

## 2. How Fast Do Agents Rot

编号与题名匹配：[arXiv:2609.01660](https://arxiv.org/abs/2609.01660)，2026-08-31 提交；[PDF](https://arxiv.org/pdf/2609.01660) 可读。HTML v1 返回 404，只是 HTML 版本缺失，非论文失效。

论文报告 10,664 条轨迹、9 个模型、4 类合成任务、5 种 horizon、3 类上下文条件。ToolQA 为隐藏链节点逐步检查任务；论文所说 16 步内下降至近零绑定此受控任务，不能推广为所有 Agent 的固定寿命。研究指出限制上下文未消除衰减且可能更差；这也不证明任何压缩方法必然无效。

作者公开仓库：[shubmittal/agent-horizon-degradation](https://github.com/shubmittal/agent-horizon-degradation)。笔记应写作“特定任务与模型设置下的实测衰减”，保留合成任务和固定解码设置的边界。

## 3. HORIZON

找到一手论文：[The Long-Horizon Task Mirage?](https://arxiv.org/abs/2604.11978)，[HTML](https://arxiv.org/html/2604.11978v1) 可读。

原文所称 3,100+ 轨迹、四个任务域和 human–judge κ≈0.84 可核对；κ 的人工核验仅 40 条试点轨迹，人际一致性 κ≈0.61。研究明确不同任务域有不同崩溃区间，不能定义统一步数阈值。

未在所查主文中找到“40 步流程第 15 步不可逆错误”这一指定案例，宜保留为文章的机制示例，不归成论文已测事实。论文主文与附录部分模型命名还有不一致，不适合把它的模型细节再扩大推论。

## 4. LUMINA

找到一手论文：[LUMINA](https://arxiv.org/abs/2601.16649)，[HTML](https://arxiv.org/html/2601.16649v1)、[PDF](https://arxiv.org/pdf/2601.16649) 可读。

论文以 ListWorld、TreeWorld、GridWorld 控制任务复杂度，分别注入规划、状态跟踪、历史剪裁 oracle。Qwen3 主实验为非 thinking、温度 0.7，另有 Gemma 3 与 GPT-4o 实验。支持“步准确率高仍可能整任务失败”，且历史剪裁收益随环境和模型改变。

文章“Qwen3-8B 短视野约60%→长视野约5%”未在可提取正文中找到直接数值；图3为分环境曲线，不能作为全场景统一成绩。原生 PDF 截图调用未返回可见图像，因此未逐点核验图3近似读数。建议标注原文近似图读数待核，或只保留有文字支持的趋势和条件。

## 数学表达需补的边界

精确链式法则为 P(全部步骤成功)=P(S1)×P(S2|S1)×…；若各步条件成功率均为 p，就得到 p^n；把孤立测得的边际成功率直接相乘还需额外假设。校验与恢复会改变事件定义和成功率，不能直接把每步边际成功率相乘。

## 可直接引用的补充勘误

### “16 步近完美到近零”需按表2收窄

[How Fast Do Agents Rot PDF](https://arxiv.org/pdf/2609.01660) 表2（第6页）给的是 ToolQA、natural context regime、H=2/4/8/16 的 task success：GPT-4o-mini 为 1.00/1.00/0.20/0.07，Claude-3-Haiku 为 1.00/0.47/0.00/0.00；Qwen2.5-7B 则为 1.00/0.07/0.13/0.33，Llama-3.2-1B 从 H=2 就已是 0。即使论文摘要作了“every model”概括，也不能在笔记里把它升级成逐模型、跨任务通用规律。可写：“文章援引研究称16步内崩溃；该研究表2实际显示多个模型下降，但并非每个模型都从近完美降至近零，且结果绑定 ToolQA 合成隐藏链任务。”

### HORIZON 模型名称不一致

主文第4节说 GPT-5-mini、Claude-4-Sonnet；附录 F 的同一批总量下，Figure7 说明又写 GPT-4o-mini、Claude 3.5 Sonnet。笔记可以保留文章“GPT-5/Claude”声称作为来源转述，并用脚注指出 v1 内部命名冲突，不能认作模型横向排名证据。四域确为 WebArena（Web）、AgentBench（OS）、MAC-SQL（Database）、Isaac Sim（Embodied）。原文将 40 步中第15步不可逆错误归于 HORIZON，未在一手主文定位，按机制示例保留。

### LUMINA 数字的可定位边界

Figure3 对照 Qwen3-8B 与 Qwen3-32B：ListWorld 横轴是 pop 次数，TreeWorld 是节点数，GridWorld 是网格尺寸，不能把横轴一概称为“依赖动作步数”，也不能把三环境合成一个 60%→5% 值。正文第4.4节只明确支持 horizon 加长、整任务成功率下降、步准确率仍可大于60%。文章的 60%→5% 保留为“原文近似值，未逐点确认对应环境/难度”，避免静默删除。
