# SplitPartUDF：字面分隔符与闭区间切片设计

对应代码：[SplitPartUDF.java](SplitPartUDF.java)。该类直接继承 `GenericUDF`，将字符串拆成若干段，再提取一段或连续多段，适合解析组合标识、层级路径和简单的分隔字段。

## 先明确位置与返回结果

函数接收 `source、separator、start`，以及可选的 `end`。位置从 `1` 开始，范围为闭区间；省略 `end` 时，取 `end = start`。

| 输入含义 | 结果 |
| --- | --- |
| `'a,b,c,d'`，分隔符 `','`，范围 `2..3` | `'b,c'` |
| `'a|b|c'`，分隔符 `'|'`，取第 `2` 段 | `'b'` |
| `'a,b,'`，分隔符 `','`，范围 `2..3` | `'b,'` |
| 第 `10` 段超过实际段数 | `''` |

任一参数为 SQL `NULL` 或 `start < 1` 时返回 `NULL`；`end < start` 时抛出 `HiveException`。空分隔符被定义为“不拆分”，直接返回原字符串，但仍要先通过起止范围的合法性检查。

## initialize：一次确定参数形式

`checkArgsSize(arguments, 3, 4)` 限制参数数量。前两个参数准备字符串转换器，位置参数准备整数转换器；只有调用方提供第四个参数时才为 `end` 创建转换器。

转换器数组按实际参数数量分配。逐行读取位置时使用 `Integer`，先判断 `null`，再参与比较，避免直接拆箱成 `int` 导致空指针异常。

## 为什么把分隔符当成字面文本

Java 的 `String.split` 接受正则表达式。字符 `|`、`.` 或组合 `.*` 都有特殊含义，直接作为分隔符传入会改变拆分结果。本函数的契约是按完整文本分隔，因此使用：

```java
String[] parts = source.split(Pattern.quote(separator), -1);
```

`Pattern.quote` 对整个分隔符进行转义，避免维护容易遗漏的特殊字符清单。参数 `-1` 保留尾部空段，使 `'a,b,'` 拆分后仍有第三段。

空段是数据的一部分，不应在不知道业务含义时自动删除。保留它，也能让后续的分段位置保持稳定。

## 如何把闭区间转成数组切片

业务范围 `[start, end]` 是一基闭区间，Java `Arrays.copyOfRange` 使用零基半开区间。对应转换为：

```java
String[] selected = Arrays.copyOfRange(
        parts, start - 1, Math.min(end, parts.length));
```

`start - 1` 修正起始下标，`Math.min` 将结束位置限制在实际长度内。若 `start > parts.length`，函数提前返回空字符串，避免创建非法切片。

最后通过 `String.join(separator, selected)` 用原分隔符拼接。这里拼接的是片段内容，不能再次使用正则转义后的分隔符，否则返回值会混入转义字符。

## 设计取舍与边界

完整拆分后再切片，代码清晰且便于核对下标，代价是会为所有片段分配空间，即使只需要其中一小段。文本很长而只提取开头片段时，可以考虑扫描式实现，但必须保留相同的空段和范围规则。

本文件仅依赖 Java 标准库与 Hive/Hadoop 类型接口，按 Hive 1.2.1 API 编写。它处理字面分隔符，不识别 CSV 引号、转义逗号或引号内的换行；这些格式需要专门的解析器。
