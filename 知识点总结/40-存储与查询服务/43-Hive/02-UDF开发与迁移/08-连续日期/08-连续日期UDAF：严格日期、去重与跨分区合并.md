# ConsecutiveDateUDAF：日期归一化、集合合并与连续区间扫描

对应代码：[ConsecutiveDateUDAF.java](ConsecutiveDateUDAF.java)。该类计算一个分组内最长的连续活跃天数，输入为 `yyyyMMdd` 字符串，输出为 `INT`。它计算最长区间，不限于最近一次连续区间。

## 从日期样例理解问题

输入 `20261003、20261001、20261002、20261002、20261010` 时，最长连续天数为 `3`。输入可以乱序，同一天重复出现只算一天。

这个问题同时要求校验真实日期、去重、排序和跨分区合并。直接统计输入行数，或者只在相邻输入行之间比较日期，都无法满足这些条件。

## 解析器与求值器的职责

外层 `ConsecutiveDateUDAF` 的 `getEvaluator` 限制输入为一个 STRING 参数。内部 `ConsecutiveDateEvaluator` 再按阶段选择如何读取输入、存储日期和生成结果。

`initialize` 并不是该 UDAF 的核心入口；聚合实现使用 `init`，它在不同模式下接收不同的检查器。原始数据阶段使用基本类型检查器读取字符串，合并阶段使用列表检查器读取上游状态。

## 严格日期解析为什么不能只检查八位数字

`20260230` 虽然是八位数字，却不是有效日历日期。代码先判断长度，再使用严格格式解析：

```java
private static final DateTimeFormatter FORMAT = DateTimeFormatter.ofPattern("uuuuMMdd")
        .withResolverStyle(ResolverStyle.STRICT);
```

`uuuu` 表达连续年份，配合严格解析直接得到 `LocalDate`，避免把 `yyyy` 的纪年年份与严格日期解析混用。日期格式器不可变，可作为静态常量复用。

SQL 空值、格式不符合要求或非法日历日期都被忽略。有效日期转换为 `LocalDate.toEpochDay()`，即相对纪元的整数日序号。两个相邻日历日的序号相差一，不需要自己处理跨月、跨年和闰日规则。

## 为什么用 TreeSet 保存状态

`State.days` 是 `TreeSet<Long>`，自动去重并保持从小到大的顺序。每个分组各有自己的集合，`reset` 清空它，避免分组之间串值。

集合只保留不同日期，不保存同一天的所有事件。设某组有 `d` 个不同有效日期，状态空间为 `O(d)`，单次插入为 `O(log d)`。它是精确算法，因此状态仍会随该组日期跨度增长。

## 分布式聚合必须保留什么信息

只保留每个分区的最长天数是不够的。分区 A 包含 10 月 1、2 日，分区 B 包含 10 月 3、4 日，两者最长都为 2，但合并后的最长应为 4。

本实现直接把日期集合用作可合并状态。合并操作是集合并集，满足结合律、交换律和幂等性；重复日期与合并顺序都不会改变最终集合。

| 模式 | 输入 | 输出 |
| --- | --- | --- |
| `COMPLETE` | 原始日期字符串 | 最长天数 INT |
| `PARTIAL1` | 原始日期字符串 | 日序号列表 ARRAY<BIGINT> |
| `PARTIAL2` | 日序号列表 ARRAY<BIGINT> | 合并后的日序号列表 |
| `FINAL` | 日序号列表 ARRAY<BIGINT> | 最长天数 INT |

`terminatePartial` 创建新的 `List<LongWritable>`，而不是把内部 TreeSet 直接交给下游。一方面让实际对象符合列表检查器，另一方面避免继续修改聚合状态时影响已经输出的部分结果。

`merge` 通过 `ListObjectInspector` 读取列表，再通过元素的基本类型检查器取出日序号。按检查器读取，不把传入对象强行当成某一种具体 Java 集合或元素表示。

## 最终扫描如何得到最长区间

有序集合为“判断相邻日序号”提供了条件。扫描维护三个量：上一日 `previous`、当前连续长度 `current`、已知最大长度 `longest`。

```java
current = previous != null && day == previous + 1 ? current + 1 : 1;
longest = Math.max(longest, current);
previous = day;
```

第一天从 1 开始；当前日与上一日相差一时延长连续段，否则重新计数。集合已去重，所以同一天不会打断或增加区间。空集合完全不进入循环，最大值保持为 0。

## 适用边界

输入必须预先归一到业务日期。该函数接收的不是事件时间戳，不负责选择业务时区，也不会判断时区转换前后应归属哪一天。最终扫描为 `O(d)`，部分结果输出与合并也要传递日期集合，不能将“每天只存一次”理解为固定大小的状态。

实现按 Hive 1.2.1 API 与 Java 8 日期库编写，所有求值器和状态类都在同一文件中。它适用于需要精确最长连续天数、且每组日期集合规模可控的场景。
