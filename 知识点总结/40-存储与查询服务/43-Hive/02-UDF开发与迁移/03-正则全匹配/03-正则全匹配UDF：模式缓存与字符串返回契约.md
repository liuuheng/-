# RegexpExtractAllToArrayUDF：模式缓存与逐次匹配设计

对应代码：[RegexpExtractAllToArrayUDF.java](RegexpExtractAllToArrayUDF.java)。该类直接继承 `GenericUDF`，查找所有不重叠的完整匹配，再把结果拼接为字符串。类名沿用项目命名，但实际输出是 `STRING`，不是 `ARRAY<STRING>`。

## 输入和结果的精确含义

前两个参数为原字符串和正则表达式，第三个参数为可选分隔符，默认使用逗号。

| 原字符串与模式 | 结果 |
| --- | --- |
| `'a12b34'` 匹配数字串，默认分隔符 | `'12,34,'` |
| `'a12b34'` 匹配数字串，分隔符 `';'` | `'12;34;'` |
| `'abc'` 匹配数字串 | `NULL` |

每次匹配后都会追加分隔符，包括最后一次。代码刻意保留带尾部分隔符的字符串契约，没有在末尾删除分隔符。

任一显式输入为 SQL `NULL` 时返回 `NULL`。没有累积出任何字符时也返回 `NULL`。非法正则抛出带原因的 `HiveException`，因为表达式错误属于规则错误，应与普通的“没有匹配”区分。

## initialize：保存转换器，清空模式缓存

初始化检查参数数量为两个或三个，并为每个输入准备字符串转换器。输出声明使用 `writableStringObjectInspector`，因此逐行结果返回 `Text`。

`cachedRegex` 和 `cachedPattern` 在初始化时清空，避免同一对象重新初始化后沿用旧缓存。它们是 `transient` 字段，属于实例的运行期派生状态。

## 为什么 Pattern 可缓存，而 Matcher 每行重建

`Pattern.compile` 将表达式编译成可匹配的模式。相同规则处理大量行时，每行重新编译属于重复工作。本函数用两个字段只缓存最近使用的模式：

```java
if (!regex.equals(cachedRegex)) {
    cachedPattern = Pattern.compile(regex, Pattern.DOTALL);
    cachedRegex = regex;
}
```

表达式改变才重新编译，编译成功后才更新对应的字符串键。缓存容量固定为一项，因此不会随着规则数量增长而无限占用内存；如果规则在两种值之间反复切换，则仍然需要反复编译。

`Matcher` 保存具体输入和当前匹配位置，具有可变状态，所以通过 `cachedPattern.matcher(source)` 为当前行单独创建。缓存模式与复用匹配进度是两件不同的事。

## find 与 group 如何形成结果

`matcher.find()` 按顺序寻找下一个匹配，`matcher.group()` 读取完整匹配，而不是某个捕获组。`StringBuilder` 只在当前行使用，连续追加“匹配项＋分隔符”。

`DOTALL` 允许点号匹配换行，但不启用忽略大小写，也不会改变行首、行尾锚点的多行语义。匹配耗时取决于表达式和输入，缓存编译结果不能消除复杂正则的回溯代价。

## 返回字符串的取舍

返回 `STRING` 便于接入已有的字符串字段，但无法天然区分“匹配内容里含分隔符”与“匹配项之间的分隔符”。如果下游要逐项处理，应另行设计 `ARRAY<STRING>` 的返回类型，并同步修改检查器和返回对象。

正则可以匹配零长度内容：如果分隔符非空，仍可能积累出分隔符；如果零长度匹配配合空分隔符，最终字符串可能为空并返回 `NULL`。因此不能把 `NULL` 简单解释成“正则从未匹配成功”。

实现基于 Hive 1.2.1 API 与 Java 标准正则库。它不依赖自定义公共基类，也没有跨实例共享的缓存。
