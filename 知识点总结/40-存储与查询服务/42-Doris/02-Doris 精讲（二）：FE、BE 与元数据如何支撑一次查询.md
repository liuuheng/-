# Doris 精讲（二）：FE、BE 与元数据如何支撑一次查询

提交 `SELECT SUM(amount) FROM t_order WHERE dt = '2026-05-15'` 时，FE 需要找到表和分区，决定哪些节点扫描，并把计划交给 BE。要理解 FE 元数据，先区分 SQL 执行所需的目录信息、节点上的物理文件，以及能够在重启后恢复的状态。

## 一、FE 如何把表名变成可执行的扫描范围

在存算一体中，FE 根据当前数据库解析 `t_order`，用 Schema 判断列类型，把日期谓词和分区边界比较，再通过目录定位 Tablet 与其副本。BE 读取对应的列式数据并执行计算。分区信息在 FE 可查，只说明 FE 能定位并组织扫描。

| FE 管理的对象 | 订单示例中的用途 |
| --- | --- |
| 数据库、表 Schema、分区、Tablet、副本分布 | 检查字段类型和分区范围，定位需要扫描的分片 |
| 导入、Clone、副本修复、Schema Change 等作业信息 | 协调作业与后台任务 |
| 用户、角色、授权 | 决定当前会话能否查询或变更表 |
| FE、BE 节点信息及角色、拓扑 | 协调节点管理与任务调度 |

## 二、新建完一个分区，FE 重启后凭什么找得到

假设 5 月 14 日的数据已在快照中，随后又新增了 5 月 15 日分区。经典 FE 的元数据设计将目录对象保存在内存中，变更通过持久化的元数据日志记录。在重启时，先装载 image 快照，再重放快照之后的变更，恢复出包含两个分区的目录。FE 之间通过日志同步元数据。这里的快照和日志描述的是目录的恢复过程。

`meta_dir` 指向元数据目录。经典布局中的 `bdb/` 保存 BDB JE 日志相关数据，`image/` 保存镜像等文件。运行日志 `fe.log` 可以帮助排查，但它的存在无法证明元数据日志和快照能完整恢复。作业的瞬时状态也不一定都进入持久化日志或同步到每个 FE。

## 三、切换到存算分离，哪些对象换了管理位置

存算一体的 BE 除列式业务数据文件外，还持有 Tablet、Rowset 等本地存储元数据。存算分离后，FE 仍承担 SQL 入口、查询规划和 SQL 层目录管理，共享存储保存数据文件，Meta Service 管理数据层的 Tablet、Rowset 与导入事务等元数据。查看导入版本问题时，先确认架构，再决定检查 FE 目录、BE 本地状态还是 Meta Service。

增加每个分区的 Bucket 数后，即使总字节数保持相近，系统仍要管理更多 Tablet。FE 管理压力与目录对象数量、调度活动和部署模式有关。容量规划见 [[03-Doris 精讲（三）：从订单分布反推分桶键与桶数|从订单分布反推分桶键与桶数]]，计算节点的分工见 [[10-Doris 精讲（十）：计算组如何隔离导入和查询资源|计算组如何隔离导入和查询资源]]。
