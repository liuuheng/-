# Doris 精讲（八）：NULL 如何进入列式存储和向量化执行

用户 2 的费用未知，用户 1 和 3 的费用分别是 10 和 20。用同一组数据可以看到，NULL 会改变统计结果，也需要在执行时参与过滤。是否填写默认值，应先由业务含义决定。

## 一、把三行数据放进一个列式批次

| user_id | cost |
| --- | --- |
| 1 | 10 |
| 2 | NULL |
| 3 | 20 |

Doris 向量化执行用列式 `Block` 传递一批数据。Nullable 列可以用数据列与 `NullMap` 表达。此例中，`user_id` 是 `[1, 2, 3]`，金额数据可示意为 `[10, 占位, 20]`，空值标记为 `[0, 1, 0]`。`1` 表示该位置为空，金额占位内容不参与业务计算。磁盘上空值如何表示还会受页格式、编码和压缩影响，不能把这组执行期数组理解成每行固定存一 bit。非 Nullable 列也不需要同样的空值表示。

| 计算 | 保留未知金额 | 把未知金额写成 0 |
| --- | --- | --- |
| `COUNT(*)` | 3 | 3 |
| `COUNT(cost)` | 2 | 3 |
| `SUM(cost)` | 30 | 30 |
| `AVG(cost)` | 15 | 10 |

这组数据的总金额相同，平均金额却改变了，因为计算平均值时多计了一笔已知金额。NULL 可以表示未知、缺失或不适用，0 是一个已知数值。只有业务明确缺失值等价于零时才适合填零。`NOT NULL` 约束、建表默认值、写入时缺字段以及显式写入 NULL 也应分开理解。见 [[05-Doris 精讲（五）：Unique Key 如何覆盖旧行与更新部分列|Unique Key 如何覆盖旧行与更新部分列]]。

## 二、执行 `WHERE cost > 15` 时，哪一行会留下

比较得到的逻辑真值依次是 FALSE、UNKNOWN、TRUE，`WHERE` 只保留用户 3。执行器可以批量比较数据列并结合空值标记屏蔽第二行。如果一批没有空值，也可能走更简单的计算路径。额外读取标记、合并掩码会增加一些工作，具体开销取决于空值分布、数据类型、CPU 和算子实现。

向量化描述按批处理。SIMD 描述一条机器指令处理多个元素。例如 SSE 和 AVX 是 x86 的 SIMD 指令集，一条指令能比较多少个值取决于寄存器宽度、元素类型和具体指令。向量化执行里可以同时有 SIMD、标量运算和条件处理。空值可以通过掩码合并处理，因此 Nullable 列本身无法证明执行发生了逐行分支或失去 SIMD。

### CPU 流水线为什么可能受条件分支影响

用简化的取指（fetch）、译码（decode）、执行（execute）三个阶段推演。周期 1 取指令 1，周期 2 译码指令 1 并取指令 2，周期 3 执行指令 1、译码指令 2 并取指令 3。实际 CPU 的流水线阶段、乱序执行和并行宽度更复杂。

处理条件分支时，CPU 可能预测分支方向，先执行预测路径。预测失败时，错误路径的推测工作作废并重新取指，这称为 branch mispredict 及流水线冲刷或恢复（pipeline flush）。只有执行确实产生了难预测的分支，才需要进一步分析这一项。条件移动和掩码也能在一些路径上减少分支。查询慢时，单凭数据中有 NULL 无法归因为流水线冲刷。

## 三、逐行、批处理和 Pipeline 在不同层次

| 比较项 | 经典逐行迭代 | Doris 向量化 |
| --- | --- | --- |
| 处理单位 | 算子间每次传递一行 | 一批列式数据，通常由 Block 承载 |
| 概念接口 | `next()` 取一行 | `nextBatch()` 可用来示意取一批，具体 Doris 接口以版本为准 |
| 执行代价 | 算子按行交互，调用次数可能较多 | 批量摊薄调用，连续列访问便于缓存利用和 SIMD |

Volcano 的 pull 表示上层算子向下层请求数据，批处理表示每次处理一批，两种特征可以同时存在。MySQL 8.0.20 使用 iterator executor 替换此前的执行器，比较时要注明版本和执行路径。

Doris 的 Pipeline 执行引擎负责算子任务的调度、阻塞处理与并行，CPU 流水线负责机器指令，两者都可以与向量化同时存在。回到实际查询，需要结合扫描量、算子耗时、并发等待和分布证据判断瓶颈。见 [[11-Doris 精讲（十一）：沿执行计划与 Profile 定位查询瓶颈|沿执行计划与 Profile 定位查询瓶颈]]。
