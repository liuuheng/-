# 11 综合练习：订单实时统计

## 1. 练习目标

实现一个最小订单统计作业：

1. 输入 CSV 文本。
2. 将文本解析为订单 POJO。
3. 过滤无效金额。
4. 按用户分组。
5. 汇总每个用户的消费金额。

输入：

```text
o-1,u-1,20.0
o-2,u-2,80.0
o-3,u-1,40.0
```

预期结果中，用户 `u-1` 的累计金额最终为 `60.0`。

## 3. 解析 CSV

```java
public static class ParseOrder
        implements MapFunction<String, Order> {

    @Override
    public Order map(String line) {
        String[] fields = line.split(",");
        if (fields.length != 3) {
            throw new IllegalArgumentException(
                "invalid order line: " + line);
        }

        return new Order(
            fields[0],
            fields[1],
            Double.parseDouble(fields[2])
        );
    }
}
```

- 接口。
- 泛型：`MapFunction<String, Order>`。

## 4. 转换为聚合结构

为了按用户累计金额，转换成：

```java
Tuple2<String, Double>
```

其中：

- `f0` 是用户 ID。
- `f1` 是金额。

```java
DataStream<Tuple2<String, Double>> userAmounts =
    orders
        .filter(order -> order.getAmount() >= 0)
        .map(order -> Tuple2.of(
            order.getUserId(),
            order.getAmount()

```

对应知识点：

- `map`。
- Tuple。
- 类型擦除。

## 5. 按用户聚合


对应知识点：

## 6. 完整作业

```java
import org.apache.flink.api.common.functions.MapFunction;
import org.apache.flink.api.common.typeinfo.TypeHint;
import org.apache.flink.api.java.tuple.Tuple2;
import org.apache.flink.streaming.api.datastream.DataStream;
import org.apache.flink.streaming.api.environment
    .StreamExecutionEnvironment;

public class OrderTotalJob {

    public static void main(String[] args)
            throws Exception {

        StreamExecutionEnvironment env =
            StreamExecutionEnvironment
                .getExecutionEnvironment();

        DataStream<String> lines = env.fromElements(
            "o-1,u-1,20.0",
            "o-2,u-2,80.0",
            "o-3,u-1,40.0"
        );

        DataStream<Order> orders =
            lines.map(new ParseOrder());

        DataStream<Tuple2<String, Double>> totals =
            orders
                .filter(order -> order.getAmount() >= 0)
                .map(order -> Tuple2.of(
                    order.getUserId(),
                    order.getAmount()
                ))
                .returns(
                    new TypeHint<
                        Tuple2<String, Double>>() {}
                )
                .keyBy(value -> value.f0)
                .reduce((left, right) ->
                    Tuple2.of(
                        left.f0,
                        left.f1 + right.f1
                    )
                );

        totals.print();
        env.execute("order-total-job");
    }

    public static class ParseOrder
            implements MapFunction<String, Order> {

        @Override
        public Order map(String line) {
            String[] fields = line.split(",");
            if (fields.length != 3) {
                throw new IllegalArgumentException(
                    "invalid order line: " + line);
            }

            return new Order(
                fields[0],
                fields[1],
                Double.parseDouble(fields[2])
            );
        }
    }

    public static class Order {
        private String orderId;
        private String userId;
        private double amount;

        public Order() {
        }

        public Order(String orderId,
                     String userId,
                     double amount) {
            this.orderId = orderId;
            this.userId = userId;
            this.amount = amount;
        }

        public String getOrderId() {
            return orderId;
        }

        public void setOrderId(String orderId) {
            this.orderId = orderId;
        }

        public String getUserId() {
            return userId;
        }

        public void setUserId(String userId) {
            this.userId = userId;
        }

        public double getAmount() {
            return amount;
        }

        public void setAmount(double amount) {
            this.amount = amount;
        }
    }
}
```

## 9. 阅读时常见问题

### 问题 1：为什么订单先转为 `Tuple2<String, Double>`，不能直接聚合 `Order` 吗？

可以直接聚合 `Order`，但教学示例使用 Tuple 能突出“按用户 ID 汇总金额”的核心结构：

```text
(userId, amount)
```

真实项目中，如果字段更多，建议定义具有明确字段名的 `UserTotal` POJO，可读性更好。

### 问题 2：`reduce()` 为什么可以不断产生累计结果？

对于同一个 key，`reduce()` 会把上一轮结果和新到数据继续合并。

用户 `u-1` 依次到达：

```text
(u-1, 20.0)
(u-1, 40.0)
(u-1, 10.0)
```

合并过程：

```text
20.0 + 40.0 = 60.0
60.0 + 10.0 = 70.0
```

这是流式滚动聚合，不需要等待全部数据结束。

### 问题 3：输出顺序为什么可能和输入顺序不同？

数据经过 `keyBy()` 后会重新分区。并行执行时，不同 key 的处理速度可能不同。Flink 通常保证需要的分区处理语义，但不保证不同 key 之间仍保持全局输入顺序。

### 问题 4：为什么示例遇到坏数据直接抛异常？

这是为了让错误显式暴露，便于先理解异常传播。生产场景需要根据业务要求决定：

- 严格链路：失败并报警。
- 容忍少量坏数据：输出到侧输出流。
- 数据质量问题严重：在上游修复。

### 问题 5：`.returns(new TypeHint<...>() {})` 在这个例子中一定不可省略吗？

不一定。某些编译器和代码结构下，Flink 可以推断出来。

示例显式写出 `.returns(...)`，是为了展示复杂泛型返回值推断失败时的标准解决方式，也让类型意图更明确。

### 问题 6：这段代码已经使用 Flink 状态了吗？

`keyBy(...).reduce(...)` 背后已经需要维护按 key 的聚合结果。你暂时不需要手动声明 `ValueState`。

后续使用 `KeyedProcessFunction` 实现更复杂逻辑时，才会显式接触：

```java
ValueState<Double>
```

### 问题 7：为什么示例使用 `fromElements()`，而不直接连接 Kafka？

`fromElements()` 便于把注意力放在 Java 和 DataStream API 上，不需要先部署外部系统。理解转换逻辑后，再将 Source 替换为 Socket、文件或 Kafka，核心处理链路仍然相似。
