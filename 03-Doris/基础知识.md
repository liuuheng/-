问题：说明：字段最好有默认值，而不是null

回答：OLAP 系统喜欢“默认值”而不是 NULL
 ```text
 doris NULL 并不是“空值不存” 而是 每一列都会额外维护一个 NULL bitmap

例如：
user_id | cost
1       | 10
2       | NULL
3       | 20

实际存储：
data列:     [1, 2, 3]
cost列:     [10, -, 20]
null bitmap:[0, 1, 0]




NULL 会影响“向量化直接过滤”
只要是“向量化执行 + SIMD + 列式处理”的系统，NULL 都会带来类似问题。

不是“不能向量化”，而是“不能纯 SIMD 一步完成过滤”  “降低纯向量化效率，但仍然是向量化执行”

“向量化直接过滤”指的是 SIMD 批处理列数据进行过滤；而 NULL 会引入额外的 bitmap 判断和分支逻辑，使过滤过程无法完全纯 SIMD 化，从而带来轻微性能损耗。

SIMD 单指令多数据 一条 CPU 指令，同时处理多个数据。

从CPU角度而言：
没有NULL的情况下：
    AVX/SSE 向量指令
    → 8/16 个数一起比较
    → 直接输出 mask

有NULL的情况下：
    1. 先 load null bitmap（额外内存访问）
    2. 做 branch 判断
    3. 再 SIMD compare
    4. merge 结果

关键损耗：
memory access 增加
branch mispredict 风险  分支预测失败   
    branch mispredict（分支预测失败）是 CPU 猜错 if/else 执行路径导致的流水线清空；在 Doris 这类向量化 OLAP 引擎中，NULL 和随机条件会增加 branch，从而降低 SIMD 与流水线效率。
pipeline 不连续
| 时钟周期   | 阶段                                   |
| ------ | -------------------------------------- ----|
| cycle1 | 指令1 fetch                                |
| cycle2 | 指令1 decode + 指令2 fetch                 |
| cycle3 | 指令1 execute + 指令2 decode + 指令3 fetch |
CPU 不是“执行完一条指令再执行下一条”，而是像工厂流水线一样，多条指令同时处于不同阶段。
CPU 同时处理多条指令  （指令有多个阶段）  最终：不同指令同时占据不同阶段。

if 会破坏 流水线：不知道后面执行哪条路径  -> cpu 会猜测 大概率 true  于是：提前执行 true 分支
但是：如果实际是 false  -> 进行pipeline flush （1. 清空流水线  2. 丢弃错误计算  3. 重走正确路径）


如果 CPU流水线疯狂flush 性能暴跌。

CPU 流水线（Pipeline）是让多条指令像工厂流水线一样并行执行的机制；if/else 和 NULL 会打断流水线，导致 branch mispredict 和 pipeline flush，从而降低 Doris 等 OLAP 引擎性能。
 ```


问：mysql 和Doris的区别在哪里

回答：
```
Volcano 模型(mysql)采用 row-based 的 pull 执行（next()），
而 Vectorized 模型(doris)采用 batch-based 的向量化执行（nextBatch()），
通过减少函数调用和利用 SIMD 提升 CPU 利用率。

Volcano  处理单位  row   接口  next()  mysql 
Vectorized  处理单位  batch 接口  nextBatch()  Doris
```
