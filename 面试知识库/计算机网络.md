##### 计算机网络

##### 浏览器输入 URL 后的完整链路

Q：在浏览器输入 URL 到页面展示，底层经历了哪些过程？
A：浏览器先解析 URL、检查缓存和 HSTS，再通过本地缓存、hosts、递归 DNS 获取 IP；与目标建立连接，HTTP/1.1、2 通常先 TCP 三次握手，HTTPS 再做 TLS 握手和证书校验，HTTP/3 使用 QUIC。请求经过 CDN、负载均衡、网关和应用，服务可能访问缓存、数据库后返回状态码、头和正文。浏览器解析 HTML 构建 DOM，解析 CSS 构建 CSSOM，生成渲染树并布局、绘制；遇到脚本和子资源继续请求，连接可复用。实际排障用 DevTools 分解 DNS、connect、TLS、TTFB、download，服务端结合网关 trace 和日志定位，不能把所有慢都归因于网络。

##### 知识点补充

DNS 可能返回 CDN 边缘节点；TLS 1.3 可减少握手往返。HTTP 缓存由 Cache-Control、ETag、Last-Modified 等控制，强缓存与协商缓存行为不同。

##### TCP、UDP 与 HTTP 长短连接

Q：应用层协议有哪些？什么场景用 TCP 或 UDP？HTTP 长连接和短连接有什么区别？
A：HTTP/HTTPS、DNS、SMTP、SSH、FTP 等属于应用层。TCP 提供有序、可靠字节流和拥塞控制，适合数据库、文件传输、普通 HTTP；UDP 无连接、不保证到达和顺序，但头部小、应用可自定义可靠性，适合实时音视频、DNS 和 QUIC。HTTP 短连接每次请求都重建 TCP/TLS，握手成本高；长连接通过 keep-alive 复用连接，降低延迟和 CPU，但要管理空闲超时、连接池上限、服务端负载和半开连接。实际服务调用会设置 connect/read timeout、最大连接数、重试仅用于幂等请求，并用 P99、连接复用率和错误码验证，不能只说“TCP 可靠、UDP 快”。

##### 知识点补充

HTTP/2 在单连接上多路复用，仍受 TCP 丢包影响；HTTP/3 基于 QUIC/UDP，提供流级复用和更快握手。应用层重试可能放大流量，需退避、抖动和熔断。

##### 内网穿透的原理与安全边界

Q：内网穿透是什么，生产环境应该怎样实现和管控？
A：内网主机没有公网可达地址时，可主动向公网中转节点建立长连接，由中转节点把外部请求转发进内网；反向代理隧道、VPN/Overlay 网络和云厂商专线都是不同实现。个人工具适合临时演示，但生产不能只写“用了某个软件”。我会说明身份认证、双向 TLS、最小端口、源 IP 白名单、审计日志、限流和隧道断线重连，并优先使用企业批准的 VPN、堡垒机或零信任接入。数据库和管理端口不直接暴露公网，访问权限按人员和时间收敛，密钥定期轮换。

##### 知识点补充

内网穿透解决 NAT 后的可达性，不自动提供安全。反向隧道的公网入口、证书和中转服务器本身都成为必须加固的攻击面。
